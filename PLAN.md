# План проекта «Защита трона»

Рабочий документ с текущим состоянием, открытыми задачами и правилами разработки.
История изменений хранится в Git, история чисел — в `packages/game/src/data/balance.ts`.

## Текущее состояние

Актуально на 20 ноября 2026 года. Баланс v37.

- Для новых партий доступны четыре зала на сетке 7×11. Это Тронный зал, Мраморный зал,
  Светлица и Храм Анубиса. В игре девять стражей, восемь типов врагов, 20 волн и бесконечный режим.
- Лучник стоит 60 золота; после III ступени он выбирает «Метку охотника» или «Рикошет»
  за 120.
- После волн 5, 10, 15 и 19 игрок выбирает один из трёх бонусов. Всего доступно 12 бонусов.
  «Щедрая награда» и «Военный налог» предлагаются только после волн 5 и 10.
- Узурпатор не получает лечение. На 19-й волне четыре огра, 14 латников, три знахаря
  и два Горыныча; на 20-й волне два знахаря.
- Знахарь лечит не больше трёх наиболее раненых союзников за импульс и не лечит
  других знахарей. В бесконечном режиме одновременно выходит не больше шести знахарей.
- На v37 (`f4f1a7c`) прошёл `npm run check` с 392 тестами, проверкой форматирования,
  стиля кода через ESLint, типов и сборкой для публикации. `npm run e2e` прошёл
  в настольном и мобильном режимах браузера, включая игру без сервера.
- На сборке `f4f1a7c` штатный прогон `npm run balance` по шести залам дал 0 побед из 90
  партий. Лучший результат — 11 из 20 отбитых волн. Бот всегда берёт первый предложенный
  бонус и не покупает специализации, поэтому прогон показывает результаты только текущих
  стратегий бота.
- Полное прохождение всех 20 волн во всех залах в v37 вручную не подтверждено.

### Оформление залов и фигурок

- Четыре зала перерисованы в виде сверху. Ковёр занимает 92% ширины клетки на прямых
  участках, повороты скруглены. Узоры, пол и помост различаются по теме зала.
- В Храме Анубиса золотой анкх из Зала фараона занял клетку нижнего обелиска.
  У входа три ступени и каменный поворот, за которым начинается синий ковёр.
  Зал фараона, Колоннада и четыре ранее выведенных зала входят в архив для старых результатов.
- Все фигурки подключены в одном SVG-атласе. У каждого из девяти стражей есть облик
  для I–III ступеней. У Лучника и Баллисты по два облика для специализаций IV ступени.
  Баллиста теперь изображена на осадном станке. Магазин показывает облики I ступени.
  Огневик выглядит как пламя, Морозко — как снежинка. На поле видны
  отдача Пушкаря, бросок сети Ловчего, качание Звонаря и открытая Казна III.
  Фигурки врагов покачиваются при движении и учитывают направление пути на повороте.
- Объединение соседних стражей в отряды и стражи на несколько клеток показаны в визуальных
  прототипах. Для оценки этих идей нужна проверка читаемости заполненного поля на телефоне.
- После перерисовки прошли `npm test` с 389 тестами, `npm run typecheck`, `npm run lint`
  и `npm run e2e`. В Chrome проверена отрисовка всех фигурок на поле и в магазине
  при размерах экрана компьютера и телефона.

## Ближайшие задачи

Сначала исправить игровые правила, затем подтверждать проходимость залов и менять числа
баланса. Проверку ответов API, доступность диалогов и пометку результатов рейтинга можно
сделать параллельно. Изменения схемы рейтинга зависят от проверки восстановления базы и
отката приложения.

  Добавить тест с тремя целями на отрезке полёта и проверить, что перестановка врагов в

### 5. Ускорить рейтинг и отрисовку

На 100 000 синтетических записей в SQLite в памяти медиана общего запроса топа составила
около 100 мс, подсчёта места после отправки — около 106 мс. Это локальные замеры
запросов. Они выполняются синхронно и могут задерживать ответы `/api/health`, поскольку
обрабатываются в том же потоке.

- [ ] Формировать прямые условия по залу и версии баланса для заданных фильтров.
  Проверка плана запроса показала, что с двумя прямыми условиями SQLite использует
  существующий индекс. Перепроверить остальные варианты фильтрации на ожидаемом
  объёме данных.
- [ ] Записывать партию и обновлять лучший результат одной транзакцией. Обе операции
  должны либо завершиться вместе, либо вместе отмениться при ошибке. Считать общий
  топ из лучших результатов. Проверить порядок при равном счёте и выдачу места игрока.
- [ ] Измерить задержку `/api/health` одновременно с запросами рейтинга. Если ответы
  всё ещё задерживаются, вынести работу с базой в отдельный рабочий поток.
- [ ] Измерить время кадра поздней волны в мобильном браузере. Бонусы Звонаря и

## Правила баланса

- Страж должен иметь собственную полезную роль, но без универсально лучшего выбора.
- Основные текущие проверки находятся в `packages/game/test` и
  `tools/balance/compact-roles.test.ts`.
- Любое изменение игровых чисел или поведения симуляции, влияющее на результат партии,
  требует обновления `BALANCE_VERSION`.
- Изменение баланса проверяется через `npm run towers`, `npm run balance`, `npm run check`
  и ручную партию.
- Зелёные технические тесты не заменяют подтверждённое ручное прохождение.

## Устройство проекта

- `packages/game` — правила, данные баланса и уровни; чистый TypeScript без Vue и DOM.
- `apps/web` — Vue-интерфейс, Canvas-отрисовка, звук и клиент API.
- `apps/server` — Fastify API и SQLite.
- `packages/contracts` — общие схемы и типы API.
- `tools/balance` — симуляции ботов и измерения баланса.
- `deploy` — release-скрипты, nginx, pm2 и резервное копирование.
- `.github/workflows` — проверки и автоматическая выкладка.

## Рабочие правила

- Игровая логика остаётся детерминированной и не зависит от Vue, DOM и Node.
- Схемы API меняются согласованно в `packages/contracts`, клиенте и сервере.
- Секреты не коммитятся.
- Изменения интерфейса проверяются через `npm run e2e`.
- Перед публикацией выполняется `npm run check`.
- Изменения в `main` автоматически деплоятся на сервер.

## Команды

```bash

npm run dev:server      # API
npm run towers          # эффективность башен
npm run balance         # симуляция стратегий по залам

npm test                # тесты
npm run e2e             # браузерная проверка
npm run check           # форматирование, линтер, типы, тесты и сборка
```
