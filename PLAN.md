## Открытый вопрос: площадка

Где живёт игра? От этого зависит, как игрок входит и откуда берутся друзья (этап 4):

| Площадка | Вход | Друзья |
|---|---|---|
| Telegram (мини-приложение) | Telegram передаёт подписанные данные игрока, сервер проверяет подпись токеном бота | Ссылки-приглашения или по чатам |
| VK Mini Apps | Подписанные параметры запуска, сервер проверяет подпись | Список друзей из VK с разрешения игрока |
| Просто сайт | Свой вход (например, через VK ID или Яндекс ID) | Ссылки-приглашения «добавь меня в друзья» |

⚠️ Для Telegram и VK игру открывают внутри их приложений во фрейме — тогда заголовок `X-Frame-Options` в `deploy/nginx/throne-security.conf` придётся заменить.

## Правила работы

1. **После каждого шага игра работает** и `npm run check` зелёный. Для изменений в интерфейсе или игре — ещё и `npm run e2e`. Новое поведение — новая проверка в `apps/web/e2e/smoke.mjs`.
2. Маленькие коммиты с понятными сообщениями.
3. **Всё, что попало в `main`, само уезжает на сервер.** Поэтому в `main` — только рабочее. Крупное делаем в отдельной ветке (там `check.yml` проверяет каждый пуш) и сливаем в `main`, когда всё зелёное.
4. **Секреты (пароли, токены, ключи) не коммитим никогда.** На сервере они лежат в `.env`, для Actions — в GitHub Secrets.
5. Баланс меняем только с проверкой: `npm run towers`, `npm run balance`, `npm test`. После любой правки чисел поднимаем `BALANCE_VERSION` и пишем в комментарии рядом, что поменяли.
6. Не теряем то, что уже хорошо: фиксированный шаг симуляции, управление с клавиатуры, aria-атрибуты, `prefers-reduced-motion`. И не ломаем то, что перечислено в [«Подводных камнях»](#подводные-камни-не-ломать).
7. **Переименования и перестановки кода не меняют поведение.** Логика детерминированная, поэтому проверка простая: вывод `npm run towers` до и после совпадает до символа, вывод `npm run balance` — тоже (кроме времени «за N мс»). Любое расхождение — нечаянно изменённая формула. ⚠️ Рисование так не проверить: после правок в `apps/web/src/render/` запусти игру и посмотри волну глазами.
8. **Команды на сервере выполняет владелец сам** и присылает вывод. Claude по SSH на сервер не ходит: даёт команды небольшими порциями, объясняет каждую и что ожидается в ответе. Настройки сервера — файлами в `deploy/`, на сервер их копируем (`scp`), а не правим руками на месте.

### Как называем вещи в коде

Код пишем так, чтобы его можно было читать без подсказок. Имена — полные английские слова. Комментарии — по-русски и объясняют «почему», а не пересказывают код.

| Понятие | Пишем | Не пишем |
|---|---|---|
| Клетка поля: столбец и строка | `cell`, `col`, `row` | `c`, `r`, `tile` |
| Радиус | `radius` | `r` |
| Ступень улучшения башни (с нуля: 0 — это «I») | `tier`, `def.tiers` | `lv`, `level` |
| Карта | `level` (`LevelDef`, `game.level`) | — |
| Урон и вид урона | `damage`, `damageKind` | `dmg` |
| Пауза между выстрелами и сколько её осталось | `cooldown`, `cooldownLeft` | `rate`, `cd` |
| Да/нет | `isDead`, `isPaused`, `isMuted`, `isReady` | `dead`, `on`, `ok` |
| Переменная в цикле или стрелочной функции | `enemy`, `tower`, `shot` | `e`, `t`, `s` |

- Короткие имена, которые оставляем, потому что их знают все: `x`, `y`, `i`, `id`, `dt` (шаг времени), `hp`, `ctx` (только контекст canvas), `def` (описание: `tower.def`), `cols`/`rows`.
- Число «из воздуха» посреди формулы выносим в константу с именем и комментарием: `LINE_SHOT_HIT_MARGIN = 0.1`, а не просто `0.1`. Числа баланса остаются данными в `data/*.ts`, координаты рисунков — в `render/`.
- Хитрые однострочники разворачиваем: вложенные тернарные операторы, `;(a ?? b)(x)`, `a = b = c`, `if (--count <= 0)`.
- CSS-классы — тоже словами: `.card-name`, а не `.nm`.
- Не переименовываем то, от чего зависят данные игроков и инструменты: ключи `localStorage` и формат рекорда `{ score, wave }`, `window.__throne`, id башен и врагов, названия событий игры, npm-скрипты.

## Этап 5. Защита от читов (когда понадобится)

Счёт сейчас считается в браузере, и его можно подделать. Для рейтинга среди друзей это терпимо; если станет важно:

- [ ] В состоянии игры — целый номер шага `tick`, время считается как `tick × шаг`. Сейчас время — дробное число, которое копит погрешность. ⚠️ Меняет значения времени в мелких знаках: сверить вывод `npm run towers` и `npm run balance` до и после
- [ ] Действия игрока становятся данными: `{ tick, type: 'build', towerId, col, row }`. Игра применяет их одной функцией и сама ведёт журнал. Старые методы (`build`, `sell`…) остаются тонкими обёртками
- [ ] Пауза, скорость и накопитель реального времени переезжают из логики игры в браузер: это «часы» игрока, а не правила
- [ ] На сервер отправляется список действий, а не счёт; сервер прогоняет ту же логику из `packages/game` и сам считает счёт
- [ ] Если в логике понадобится случайность — только генератор с зерном (seed), одинаковый в браузере и на сервере

Основа уже есть: в логике нет случайности, одинаковые действия дают одинаковое состояние (на это есть тест с полным журналом событий), а аргументы методов игры проверяются.

**Готово, когда:** результат с подделанным счётом сервер не принимает.

```
    bot.test.ts (тесты-сторожа баланса). Пакет игры берут только через @throne/game

  deploy/               ← всё про сервер: nginx/ (конфиги сайта), pm2/ecosystem.config.cjs (как
                          запускать API), scripts/deploy-web.sh и deploy-server.sh (ручная
                          выкладка сайта и API, запускаются на Mac), server/after-upload.sh
                          (выполняется на сервере после заливки API), known_hosts
                          (публичный ключ сервера для автодеплоя)
  .github/workflows/    ← check.yml (проверка веток и pull request), deploy.yml (автодеплой из main)
```

**Как игра и Vue общаются** (как родитель и ребёнок):
- **Vue → игра:** кнопки вызывают методы: `game.build('archer', 5, 11)`, `game.startWave()`…
- **Игра → Vue:** игра сообщает о событиях (`game.on('kill', …)`, `leak`, `victory`, `defeat`…). На них подписаны стор (звук, экраны, «подпрыгивания» в шапке) и `render/effects.ts` (искры, тряска).
- **Числа для интерфейса:** каждый кадр игровой цикл (`composables/useGameLoop.ts`) делает три вещи: `game.advance(dt)` → `renderer.draw()` → `store.syncHud()`. `syncHud()` копирует золото, жизни, волну и т.п. в реактивный объект `store.hud`.

## Куда движется структура

Границы проведены правильно: правила игры отдельно от интерфейса, рисование отдельно от Vue, наружу пакет смотрит через один `index.ts`. Меняем только то, что мешает ближайшим этапам, и только когда этап до этого дошёл. Что появится:

```
packages/game/src/core/      (этап 5)  + commands.ts и replay.ts: действия как данные
apps/web/src/stores/         (этап 6)  + selection.ts — выбор игрока, из game.ts
```

**Кто кого может импортировать** (обратно нельзя):

1. `packages/game` не импортирует ничего: ни Vue, ни DOM, ни Node. В нём нет `Math.random` и `Date`.
2. Снаружи в `@throne/game` заходим только через `index.ts`, не в глубину. Тестам самого пакета можно.
3. `render/` не знает про Vue, Pinia и стор: получает игру и `BoardView` аргументами.
4. `stores/` не импортирует компоненты. `audio/` не импортирует стор.
5. Сайт и сервер не импортируют друг друга. Общее лежит в `game` и `contracts`.

Охраняется само: пункт 2 — поле `exports` в `packages/game/package.json`; DOM и Node в пункте 1 — `tsconfig` пакета; `Math.random`/`Date` и импорт `vue`/`pinia` в логике, а также пункт 3 — правила в `eslint.config.js`.

**Чего не делать** (соблазнительно, но для проекта такого размера — лишнее):
- отдельные пакеты `shared`, `ui`, `utils`; деление `packages/game` на «движок» и «контент»;
- пять-шесть Pinia-сторов: состояния связаны (победа → рекорд → экран → звук), хватит двух;
- Nx, Turborepo, слои «domain/application/infrastructure», шина событий поверх `game.on`.

## API и база

Адреса — в `packages/contracts/src/paths.ts`, схемы запросов и ответов там же (TypeBox): Fastify сам отвечает 400 на всё, что не подходит под схему.

| Адрес | Что |
|---|---|
| `GET /api/health` | `{ ok: true }`, заодно проверяет базу. По нему автодеплой понимает, что API поднялось |
| `POST /api/runs` | результат партии `{ playerName, levelId, score, wavesCleared, balanceVersion }` → место игрока `{ rank, playerCount }` |
| `GET /api/leaderboard?level=…&balance=…` | 10 лучших `{ entries, playerCount }` |

- **Таблица лучших** (`apps/server/src/services/leaderboard.ts`): **одно имя — одна строка** с его лучшим результатом (так решил владелец: иначе один упорный игрок займёт все места); у равных счетов одно место, выше — кто набрал раньше. Уровни и версии баланса не смешиваются.
- **Имя** — `packages/contracts/src/player-name.ts`, правила общие для поля ввода и сервера: 1–20 символов (символов, а не байтов), без невидимых, пробелы по краям убираются. В браузере — ключ `localStorage` `throne-name`. Результат уходит сам после каждой партии со счётом больше 0 (так решил владелец).
- **Защита:** не больше 60 запросов в минуту с адреса, для `POST /api/runs` — 10. Адрес игрока Fastify берёт из `X-Forwarded-For`, но верит заголовку только от nginx (`trustProxy: '127.0.0.1'`), так что подделать его нельзя. **Проверка правдоподобия** (`services/plausibility.ts`, ответ 422): уровень существует, версия баланса — текущая, волн не больше 100, счёт не больше `maxPossibleScore` из `packages/game`. Честная защита от подделки — только [этап 5](#этап-5-защита-от-читов-когда-понадобится).
- **Мусор из топа** удаляем не руками в базе, а скриптом `apps/server/src/scripts/delete-runs.ts` (как запускать — в начале файла; сначала показывает, что удалит).
- **Без сервера** игра работает как раньше: запросы (`apps/web/src/api/leaderboard.ts`) ждут не дольше 5 с и не бросают ошибок, а возвращают `null`.
- **База** — SQLite (`node:sqlite`), режим WAL; таблица `runs`. На сервере — `/srv/throne-defense/data/throne.db`, у себя — `apps/server/data/` (в `.gitignore`). При запуске сервер применяет новые **миграции** из `apps/server/src/db/migrations/NNN-….sql`: номер последней хранится в самой базе (`PRAGMA user_version`), каждая — в транзакции. **Применённую миграцию не правим** — схему меняем только новым файлом со следующим номером. Если база новее кода (откатили код), сервер не стартует — так задумано.

## Как добавить

- **Башню:** объект `TowerDef` в `packages/game/src/data/towers.ts` и строчка в `TOWER_LIST`. Характеристики по ступеням — поле `tiers`, цены улучшений — `upgradeCosts` (их на одну меньше, чем ступеней; это проверяет тест). Поведение — функция `fire`, собирается из кирпичиков в `systems/combat.ts` (`shootHoming`, `shootLine`, `frostPulse`); без `fire` башня не стреляет (Звонарь ускоряет соседей через `fireRateBonus`, Казна приносит золото через `goldPerWave`). `defaultTargetMode` — кого бьёт сразу после постройки; `canChooseTarget` — умение переключать «первый/сильный» (кнопка в панели и клавиша T), сейчас только у баллисты. «Сильный» — по полному здоровью (`maxHp`), а не по текущему: иначе баллиста бросала бы раненого огра ради свежего бунтовщика. Что показывать в панели — поле `displayStats`. Рисунок — в `TOWER_ART` в `apps/web/src/render/towers.ts`, там же необязательный эффект выстрела `onFire`. Рисунок получает ступень `tier`: общее правило — II крупнее и с железом, III с золотом и свечением (кольцо вокруг постамента рисуется само: у II серебряное, у III золотое, с тёмным зазором — чтобы не сливалось с золотом башни). Без рисунка башня рисуется кружком. Магазин, клавиши 1–9 и панель подхватят её сами
- **Врага:** `EnemyDef` в `data/enemies.ts` и рисунок в `ENEMY_ART` в `render/enemies.ts` (`sparkColor` — цвет искр, `sparkCount` — их число, `drawOnTop` — рисовать поверх остальных). Готовые особенности: `slowResistance` (узурпатор), `heal` (знахарь лечит соседей), `splitInto` (Горыныч, погибая, распадается — те, на кого он распадается, тоже должны быть в списке врагов, это проверяет тест)
- **Уровень:** файл в `packages/game/src/levels/` по образцу `throne-hall.ts` и строчка в `levels/index.ts`. Ошибки в описании уровня (в том числе в первых 30 волнах бесконечного режима) `createLevel` сообщает понятным текстом. Первая точка пути (`pathPoints`) может лежать за краем поля — это дверь
- **Вид снаряда:** поле `look` при выстреле и рисунок в `SHOT_ART` в `render/shots.ts`

## Подводные камни (не ломать)

- **Игра не реактивна.** Объект игры обёрнут в `markRaw`. Если положить врагов в `ref`/`reactive`, Vue будет следить за каждым из них 60 раз в секунду, и игра начнёт тормозить. Интерфейсу хватает снимка `store.hud`.
- **В `packages/game` нет браузера.** В `tsconfig` нет `DOM`: если логика полезет в `document`, `window` или `localStorage`, TypeScript выдаст ошибку. Звук, эффекты, рекорд — только в `apps/web`.
- **Импорты внутри `packages/game` пишутся с расширением `.ts`** (`'./core/game.ts'`). Включены `allowImportingTsExtensions` и `erasableSyntaxOnly` (нельзя `enum` и `namespace`). Так Node 24 выполняет TypeScript напрямую, без сборки: на этом работают `npm run balance`/`towers` и сервер. То же — в `packages/contracts` и `apps/server`.
- **Методы игры не верят аргументам:** клетки только целые, id башен и врагов проверяются через `Object.hasOwn`, `NaN` в `setSpeed`/`advance` пропускается, один `advance` делает не больше 60 шагов. Это важно для сервера — не ослаблять.
- **В логике нет случайности** (`Math.random` только в рисовании: искры, покачивание). Это нужно для этапа 5; ESLint следит.
- **Новые поля в состоянии игры — «плоские»:** числа, строки, id, без ссылок на другие объекты. Так состояние потом будет проще сохранить и сравнить (этапы 5 и 6).
- **Горыныч распадается в конце шага, а не в момент гибели:** погибший кладёт «осколки» в `state.splitQueue`, а `spawnSplits` выпускает их после выстрелов. Иначе тот же взрыв задел бы и змеёнышей. Волна кончается, только когда пусты и очередь выхода, и список врагов — поэтому `spawnSplits` стоит до этой проверки.
- **Шаг симуляции фиксированный — 1/60 с.** `advance(realDt)` копит реальное время и делает нужное число шагов. `step()` ничего не делает вне фаз `build`/`wave`.
- **Скорость (×1/×2/×3) сохраняется** при «Сыграть ещё раз». На это есть тест.
- **Ключи `localStorage` — `throne-best`, `throne-audio` (настройки звука), `throne-name` (имя для общего топа) и старый `throne-muted`.** `throne-muted` (`'1'` — звук выключен) остался от версий без музыки: игра его только читает, пока нет `throne-audio`, чтобы у кого звук был выключен, тот и после обновления играл в тишине. Рекорд хранится как `{ score, wave }`, где `wave` — сколько волн отбито; эти имена менять нельзя. Рекорд читается через `parseBest`, который отбрасывает мусор, и перед сравнением перечитывается (вторая вкладка не затирает рекорд). Счёт 0 — не рекорд.
- **Клавиатура:** повторы от зажатой клавиши игнорируются, кроме стрелок. Иначе зажатый пробел начинал волну и тут же ставил паузу. Порядок проверок в `useKeyboard.ts` менять осторожно.
- **Боковая панель включается условием `(min-width: 640px) and (min-aspect-ratio: 1/1)`** (это и телефон набок). Оно повторяется в трёх media-запросах `styles/responsive.css`: основном, для ноутбука (`max-height: 760px`, карточки без описаний) и компактном (`max-height: 560px`), а запрос для низкого экрана без панели — его противоположность (`max-width: 639px`). Меняешь одно — поменяй все четыре и проверь `npm run e2e` (там есть проверки «кнопка на экране» и «карточки магазина видны целиком» на 1280×860, 1366×650, 390×844, 320×568 и 932×430).
- **Поле не перерисовывается, если ничего не поменялось.** `renderer.draw()` собирает «отпечаток» кадра (`frameFingerprint` в `render/renderer.ts`): игровое время, фаза, золото, жизни, число башен, врагов и снарядов, выбор игрока. Совпал с прошлым — кадр пропускается (в меню и на паузе 0 кадров в секунду вместо 60). Если добавляешь то, что меняет картинку **без** изменения этих данных (анимацию в реальном времени на паузе, новое видимое поле состояния) — добавь его в отпечаток, иначе картинка застынет.
- **Экран поверх поля — диалог.** Пока он открыт, шапка, поле и панель получают атрибут `inert` (в `App.vue`). После поражения и победы фокус ставится на сам экран, а не на кнопку — иначе Enter, нажатый в этот момент, перезапустит партию. В меню фокус на «Играть».
- **TypeBox не должен попасть в игру.** В `packages/contracts` схемы (TypeBox) нужны только серверу. Сайт берёт адреса, типы и правила имени; файлы со схемами сборщик выбрасывает благодаря `"sideEffects": false` в `packages/contracts/package.json`. Новое, что нужно сайту, клади в файлы без TypeBox (`paths.ts`, `player-name.ts`), а не рядом со схемами — иначе игра вырастет на ~18 КБ (gzip). Проверка: размер `index-….js` в выводе `npm run build` (сейчас ≈ 56 КБ gzip).
- **Новая `BALANCE_VERSION` — новая таблица лучших.** Сервер принимает результаты только текущей версии, а таблица показывает только её: после правки баланса топ начинается с нуля. Так задумано (v3 и v4 — разные игры). Потолок счёта (`maxPossibleScore`) считается из данных игры сам; если меняешь, *как* начисляются очки (`SCORE`, `finishWave`, `loseHp`), — проверь его: тест «ни одна стратегия бота не набирает больше» в `tools/balance/bot.test.ts`.
- **`smoke.mjs` — обычный JavaScript, типы его не проверяют.** Если переименовать поле состояния игры или CSS-класс, TypeScript промолчит: ищи старое имя в этом файле руками.
- **Необязательное поле «да/нет» сравнивай осторожно.** Незаданное поле (`drawOnTop?: boolean`) — это `undefined`, а `undefined !== false` — истина. Сначала приведи к «да/нет» (`art.drawOnTop ?? false`), потом сравнивай. Однажды на этом пропали с поля все враги, кроме босса, и ни один тест не заметил — с тех пор есть проверка «враг нарисован на поле».
- **Колонки экранов поверх поля — `grid-template-columns: minmax(0, 1fr)`** (у `.overlay`, `.sheet`, `.name-form` в `styles/overlay.css`). Без этого колонка сетки растягивается под содержимое: поле имени (браузер даёт ему ширину ≈ 20 букв) с кнопкой «Сохранить» раздвигали экран итогов шире телефона 320 px, и страница ездила вбок. По той же причине минимальный размер заголовка — 2rem: иначе «РЕЗУЛЬТАТЫ» не влезает в 320 px.
- **Клавиши игры не работают, пока фокус в поле ввода** (имя, ползунки громкости) **и пока открыты «Настройки»** — кроме Escape: он закрывает экран откуда угодно (`useKeyboard.ts`).

### Сознательно оставлено как есть (не «исправлять»)

Эти места выглядят как ошибки, но так сделано специально:
- **Перезарядка башен округляется вверх до шага 1/60 с**, поэтому башни стреляют до ~3% реже, чем написано в `cooldown`. Баланс настроен именно с этим; «исправить» — значит сделать все башни сильнее.
- **Замедление: сила и длительность обновляются по отдельности.** Слабый, но долгий Морозко продлевает действие сильного. Баланс настроен с этим.
- **Огненный шар взрывается там, где цель была в последний раз**, даже если она уже погибла.
- **Разблокировка звука висит на каждом клике/нажатии навсегда.** Safari и iOS «усыпляют» звук после звонка или переключения приложений, разбудить его можно только по действию игрока.
- **Отмена в меню «Поделиться» возвращает `'shared'`.** Интерфейс реагирует только на `'copied'`, разницы для игрока нет.
- **Продажа башни без подтверждения.** Как в большинстве игр жанра; сумма возврата сразу видна на кнопке. Золото, вложенное после начала последней волны (`tower.goldSinceLastWave`), возвращается целиком — это «отмена» случайной постройки или улучшения, кнопка тогда называется «Вернуть». Остальное — 60%. Построенная во время волны башня сразу в бою, полного возврата нет.
- **`?debug` работает и в собранной версии.** На нём держится `npm run e2e`. От подделки счёта защитит только проверка на сервере (этап 5).
- **Номера врагов и башен после «Сыграть ещё раз» начинаются заново** — для повторного прогона партии на сервере это как раз нужно.
- **Клавиши 1–9 читаются по символу, а не по положению клавиши:** на французской раскладке (AZERTY) не работают, но игра русскоязычная.
- **`npm run check` проверяет типы интерфейса дважды** (в `typecheck` и в `build`). Потеря — секунды, зато сборку нельзя запустить без проверки типов.
- **`npm audit` показывает несколько записей средней тяжести** из пакета `minimatch` в зависимостях ESLint. В игру он не попадает; перепроверить, когда выйдет обновление.

## Звук и музыка

Аудиофайлов нет: и звуки, и музыку браузер синтезирует WebAudio — генераторы тона и шума с огибающими громкости. Всё в `apps/web/src/audio/`.

- **`engine.ts`** — один `AudioContext` на всю игру и настройки (`AudioSettings` в `utils/storage.ts`: выключатель и громкость 0–100% для звуков и для музыки). Звуки и музыка идут через две «шины» — общие регуляторы громкости. Громкость ползунка возводится в квадрат: так слуху кажется, что она растёт равномерно. Контекст создаётся только после действия игрока — раньше браузер звук не разрешит (`unlock()` на каждом клике, см. ниже).
- **`music.ts`** — мелодия в ля миноре на «гуслях» (8 тактов по кругу, ноты записаны текстом: `'E4 - A4 - B4 - C5 -'`) и слои по настроению: `calm` (меню, строительство), `battle` (волна: барабан, бубен, бас), `danger` (в волне Горыныч или узурпатор: ещё и тревожный пульс), `silent` (победа и поражение — звучит мелодия итога из `sfx.ts`). Настроение меняется на начале такта, чтобы не рвать мелодию. **Ноты ставятся заранее по звуковым часам** (`context.currentTime`): `setTimeout` раз в 25 мс смотрит на 0,15 с вперёд. Играть ноты прямо по таймеру нельзя — он опаздывает на десятки мс, и ритм «плывёт». Темп музыки от скорости игры (×1/×2/×3) не зависит.
- **`gameSounds.ts`** — подписки звуков на события игры и выбор настроения (`musicMoodFor`). Стор только подключает: следит (`watch`) за фазой, волной и паузой в `hud`.
- **Пауза** глушит музыку фильтром («из-за стены»), а не останавливает. В «Настройках» не глушит, хоть игра и на паузе: игрок подбирает громкость. Свёрнутая вкладка — музыка молчит.
- **«Настройки» посреди волны** ставят бой на паузу, а при закрытии снимают её сами (иначе владельцу казалось, что игра зависла). Паузу, которую игрок поставил до настроек, не трогают.

Решения владельца:
- Отдельной кнопки музыки в нижней строке нет: на телефоне 320 px четвёртая кнопка-иконка отнимает место у «Начать волну». Вместо кнопки «Звук» — шестерёнка «Настройки» на том же месте.
- Музыка по умолчанию на 50% (усиление 0,3): громче (0,55) владелец счёл громким.
- Кнопки на экранах поверх поля — столбиком одной ширины: Играть → Лучшие результаты → Настройки.

Проверить на слух: `npm run dev`. Тревожную музыку быстро: открыть с `?debug`, в консоли `__throne.game.state.wave = 10`, «Начать волну». В `npm run e2e` состояние музыки читается через `window.__throne.music.debugState()` — играет ли, настроение, приглушена ли; как она звучит, проверки не знают. ⚠️ В меню две кнопки «Настройки» (шестерёнка под меню тоже в разметке, хоть и `inert`) — в проверках ищи кнопку внутри `getByRole('dialog')`.

## Баланс: что известно

**Как меряем выгодность башни** (`npm run towers`): башня ставится на лучшую для неё клетку, мимо идёт поток врагов, которых нельзя убить, и весь урон делится на вложенное золото. Так учитываются сразу дальность, скорострельность, броня, пробивание и взрывы. Замер приблизительный: не учитывает лишний урон по почти убитому врагу, рост здоровья врагов и то, как башни помогают друг другу.

**Версия 4** (что менялось — в комментарии к `BALANCE_VERSION` в `data/balance.ts`). Версия 3: в живой игре волны казались лёгкими, а узурпатор — стеной, поэтому обычным врагам добавили ≈22% здоровья, а узурпатора замедлили на 10%. Версия 4: у каждой башни своя работа, новые враги и башни:
- **Работа башен:** лучник — дешёвый и частый, слаб против лат; огневик — поджигает толпу: 20% урона взрывом (5/9/14), 80% горением за 3 с (19/33/53), огонь — магия, броню не замечает. Горение — «запас огня»: повторный поджог добавляет урон в запас, а не перезапускает горение. **Огонь и лёд мешают друг другу в любом порядке — их выгодно разводить по ковру:** «пар» — волна Морозко тушит горящего врага, и 75% оставшегося огня он получает сразу (облачко пара и белое число урона); «мокрый» — замедленный враг загорается вдвое хуже (пламя на нём меньше и бледнее). Множители — `STEAM_DAMAGE_MULTIPLIER` и `WET_BURN_MULTIPLIER` в `systems/combat.ts`. За это огневик сильнее, а Морозко замедляет на 45/55/65%. Боты ставят их как попало и платят штраф; учить бота разводить их пробовали — на этом извилистом поле место подальше хуже накрывает ковёр, и боты не выигрывали; Морозко — только замедляет (урон 1/2/3, раньше наносил урона на монету больше всех); баллиста — редкие сильные выстрелы против огров и узурпатора, пробивает двоих; Звонарь — стреляющие соседи (лучник, огневик, баллиста; Морозко — нет) стреляют на 15/25/35% чаще, несколько Звонарей не складываются; Казна — 12/22/35 золота за волну.
- **Урон на монету** (`npm run towers`, ступень I, против бунтовщиков / латников / огров): лучник 10 / 3 / 12, огневик 10 / 12 / 8, Морозко 4 / 4 / 2, баллиста 13,5 / 16 / 13,5. Баллиста в этом замере выглядит лучше, чем в игре: замер не считает лишний урон по почти убитому врагу, а у баллисты он самый большой (80 урона в бунтовщика с 37 здоровья). В игре боты на одних баллистах проигрывают смешанным.
- **Новые враги** заменили часть старых (а не добавились сверху — так боты падали на 4–5 волн раньше): знахарь (с 6-й волны, лечит соседей на 15% своего здоровья раз в 2,5 с), Змей Горыныч (10-я, 15-я, 17-я, 19-я волны, распадается на трёх быстрых змеёнышей).
- **Боты** (`npm run balance`, версия 4): «Только лучники» падают на 12-й волне, «Огонь и баллисты» и «Только баллисты» — на 15-й, «Смешанная без баллист» и «Смешанная со Звонарями» — на 16-й, «Смешанная с Казной» — на 17-й, «Смешанная» — на 19-й (в версии 3 «Смешанная» доходила до 19-й). Самые тяжёлые волны — 15-я (Горынычи) и 16–17-я. Бот глупый (ставит жадно, ничего не продаёт, цель баллисты не меняет — с «сильным» с начала партии он падал на 1–2 волны раньше), так что человек играет лучше, но относительную силу стратегий видно.
- **20-я волна — стена:** у узурпатора около 43 тысяч здоровья (здоровье врагов растёт до ×29 к 20-й волне). Ни одна стратегия бота её не проходит. С версии 3 он идёт медленнее (0,36 клетки/с), то есть дольше стоит под огнём башен.
- **Тесты-сторожа** в `tools/balance/bot.test.ts`: одни баллисты слабее смешанной стратегии без баллист, баллиста III — не больше чем на 25% выгоднее баллисты I, «Только лучники» именно проигрывают. Упал сторож — не обязательно ошибка: если так и задумано, поправь порог.

## Как проверять в браузере

`npm run e2e` собирает игру, сам поднимает `vite preview` и настоящий API на временной базе (порт 3101) и открывает игру в Chrome без окна через `playwright-core`. Последний сценарий — «без сервера»: запросы к `/api` обрываются, и там (только там) ошибки «Failed to load resource» в консоли ожидаемы. Скрипт — `apps/web/e2e/smoke.mjs`. Состояние игры он читает через `window.__throne` (есть только с `?debug`), а результат печатает списком строк «✓ / ✗» — по нему и видно, что проверяется. Нужен установленный Google Chrome; если его нет — `npx playwright-core install chromium`. В GitHub Actions Chrome уже есть.

Числа баланса в скрипте зашиты намеренно (золото после покупок, «урон 7 → 12», «Дальше: 12 бунтовщиков»): поменял баланс — обнови их вместе с `BALANCE_VERSION`.

На картинку смотрит одна проверка — «враг нарисован на поле»: квадрат canvas вокруг врага с врагом и без него. Остальное в `render/` проверяй глазами (правило 7).

Подсказка для новых проверок: пробел на кнопке в фокусе нажимает саму кнопку. Перед проверкой пробела снимай фокус (`blurActiveElement` в скрипте), `body.focus()` для этого не подходит.

## Словарик

- **DNS, A-запись, TTL** — строчка у регистратора домена: «имя `throne-defense.ru` — это сервер с таким-то адресом». TTL — сколько секунд провайдеры могут помнить ответ, не спрашивая заново.
- **nginx** — программа на сервере, которая отдаёт файлы сайта и пересылает запросы `/api` в Node. Один nginx обслуживает сколько угодно сайтов на одном порту — по имени сайта.
- **certbot, Let's Encrypt** — бесплатный сертификат для HTTPS (замочек в адресной строке) и программа, которая его получает и продлевает.
- **rsync, rrsync** — копирует папку на сервер, пересылая только изменившиеся файлы; rrsync на сервере разрешает ключу только rsync и только в одну папку.
- **pm2** — следит за процессом Node на сервере: перезапускает после падения и после перезагрузки.
- **cron** — расписание на сервере: «каждую ночь делай бэкап».
- **Миграции** — файлы, которые по шагам описывают, как менялась структура базы данных.
- **GitHub Actions, workflow, Secrets** — GitHub сам запускает команды на каждый пуш; workflow — файл с этими командами; Secrets — место для паролей и ключей, которых нет в коде.
- **CORS** — запрет браузера обращаться с сайта на чужой адрес. Нам не нужен: игра и API на одном адресе.
- **Детерминированность** — одинаковые действия всегда дают одинаковый результат. Без неё сервер не сможет перепроверить партию.
- **tick, seed** — номер шага симуляции; начальное число для генератора «случайных» чисел, с которым последовательность можно повторить.
- **Прототип** — у любого объекта в JavaScript есть «родитель» со встроенными свойствами. Поэтому `TOWERS['constructor']` находит не башню, а встроенную функцию. `Object.hasOwn(TOWERS, id)` проверяет только собственные ключи.
- **inert, aria-modal** — атрибуты для экрана поверх страницы: `inert` выключает всё под ним (ни кликнуть, ни дойти клавишей Tab), `aria-modal` сообщает об этом скринридеру.
- **safe-area-inset** — отступы от выреза и скруглений экрана телефона. **overscroll-behavior** — что делать, когда страницу тянут дальше края (на Android — обновление страницы).
- **og:image** — картинка, которую мессенджер показывает рядом со ссылкой.
