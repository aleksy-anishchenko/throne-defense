## Правила работы

1. **После каждого шага игра работает** и `npm run check` зелёный. Для изменений в интерфейсе или игре — ещё и `npm run e2e`. Новое поведение — новая проверка в `apps/web/e2e/smoke.mjs`.
2. Маленькие коммиты с понятными сообщениями. Крупный этап делаем в отдельной ветке и сливаем в `main`, когда всё проверено.
3. После этапа 2 всё, что попало в `main`, само уезжает на сервер. Поэтому в `main` — только рабочее.
4. **Секреты (пароли, токены, ключи) не коммитим никогда.** На сервере они лежат в `.env`, для Actions — в GitHub Secrets.
5. Баланс меняем только с проверкой: `npm run towers`, `npm run balance`, `npm test`. После любой правки чисел поднимаем `BALANCE_VERSION` и пишем в комментарии рядом, что поменяли.
6. Не теряем то, что уже хорошо: фиксированный шаг симуляции, управление с клавиатуры, aria-атрибуты, `prefers-reduced-motion`. И не ломаем то, что перечислено в [«Подводных камнях»](#подводные-камни-не-ломать).

```
                          TowerCard, TowerInfo, ControlsBar, ScreenOverlay
    src/stores/game.ts    Pinia-стор: мост между игрой и Vue
    src/render/           рисование: renderer (кадр целиком), hall (зал, трон), towers,

```

**Как игра и Vue общаются** (как родитель и ребёнок):
- **Vue → игра:** кнопки вызывают методы: `game.build('archer', 5, 11)`, `game.startWave()`…
- **Игра → Vue:** игра сообщает о событиях (`game.on('kill', …)`, `leak`, `victory`, `defeat`…). На них подписаны стор (звук, экраны, «подпрыгивания» в шапке) и `render/effects.ts` (искры, тряска).
- **Числа для интерфейса:** каждый кадр `GameBoard.vue` делает три вещи: `game.advance(dt)` → `renderer.draw()` → `store.sync()`. `sync()` копирует золото, жизни, волну и т.п. в реактивный объект `store.hud`.

Версии (ноябрь 2026): Vue 3.5, Pinia 4, Vite 8, TypeScript 6, ESLint 10, Vitest 5, Node 24.

## Подводные камни (не ломать)

- **Игра не реактивна.** Объект игры обёрнут в `markRaw`. Если положить врагов в `ref`/`reactive`, Vue будет следить за каждым из них 60 раз в секунду, и игра начнёт тормозить. Интерфейсу хватает снимка `store.hud`.
- **В `packages/game` нет браузера.** В `tsconfig` нет `DOM`: если логика полезет в `document`, `window` или `localStorage`, TypeScript выдаст ошибку. Звук, эффекты, рекорд — только в `apps/web`.
- **Импорты внутри `packages/game` пишутся с расширением `.ts`** (`'./core/game.ts'`). Включены `allowImportingTsExtensions` и `erasableSyntaxOnly` (нельзя `enum` и `namespace`). Так Node 24 выполняет TypeScript напрямую, без сборки: на этом работают `npm run balance`/`towers`, и на этом же будет работать сервер.
- **В логике нет случайности** (`Math.random` только в рисовании: искры, покачивание). Это нужно для этапа 5.
- **Шаг симуляции фиксированный — 1/60 с.** `advance(realDt)` копит реальное время и делает нужное число шагов. `step()` ничего не делает вне фаз `build`/`wave`: раньше после поражения дошедший враг «доходил» снова на каждом шаге, на это есть тест.
- **Скорость (×1/×2/×3) сохраняется** при «Сыграть ещё раз», как в оригинале. На это есть тест.
- **Ключи `localStorage` — `throne-best` и `throne-muted`**, как в оригинальной игре, чтобы не потерять рекорды. Рекорд читается через `parseBest`, который отбрасывает мусор: раньше испорченная запись роняла меню.
- **Клавиатура:** повторы от зажатой клавиши игнорируются, кроме стрелок. Иначе зажатый пробел начинал волну и тут же ставил паузу.

### Сознательно оставлено как есть (не «исправлять»)

Эти места выглядят как ошибки, и код-ревью на них указывало, но так сделано специально:
- **Перезарядка башен округляется вверх до шага 1/60 с**, поэтому башни стреляют до ~3% реже, чем написано в `rate`. Так было в оригинале, и баланс настроен именно с этим. «Исправить» — значит сделать все башни сильнее, то есть поменять баланс.
- **Разблокировка звука висит на каждом клике/нажатии навсегда.** Safari и iOS «усыпляют» звук после звонка или переключения приложений, а разбудить его можно только по действию игрока.
- **Отмена в меню «Поделиться» возвращает `'shared'`.** Интерфейс реагирует только на `'copied'`, так что разницы для игрока нет.
- **Бот ищет лучшую клетку, даже когда копит золото.** Это лишняя работа, но вся партия у бота считается за 20–80 мс.
- **`npm audit` показывает уязвимость средней тяжести в зависимостях ESLint.** ESLint работает только у разработчика, в игру не попадает, а «исправление» откатило бы его на старую версию.

## Баланс: что известно

**Как меряем выгодность башни** (`npm run towers`): башня ставится на лучшую для неё клетку, мимо идёт поток врагов, которых нельзя убить, и весь урон делится на вложенное золото. Так учитываются сразу дальность, скорострельность, броня, пробивание и взрывы.

**Версия 2** (история — в комментарии к `BALANCE_VERSION` в `data/balance.ts`):
- Баллиста ослаблена: урон 55/95/160 → 50/80/125, дальность 3,6/4/4,5 → 3,4/3,6/3,9. Раньше баллиста III была в 2–2,5 раза выгоднее лучника и огневика, потому что с дальностью 4,5 простреливала почти весь ковёр. Теперь она выгоднее примерно в 1,5 раза (дорогая и слабая в начале), а улучшения почти не добавляют выгоды.
- Урон на монету против бунтовщиков, уровень I: лучник 9,5, огневик 10, Морозко 12, баллиста 13,8. Против латников огневик (12,4) намного лучше лучника (4,7).
- **Морозко** против толпы и латников наносит больше всех урона на монету (12–19 в зависимости от уровня), хотя в описании «сам почти не ранит». Рядом с лучником он увеличивает его урон почти втрое. Боты с ним не доминируют, поэтому пока не трогали — проверить в живой игре.
- **Боты** (`npm run balance`): «Только лучники» падают на 14-й волне, «Только баллисты» и «Огонь и баллисты» — на 17-й, «Смешанная без баллист» — на 19-й, «Смешанная» доходит до 20-й и проигрывает узурпатору. Бот глупый (ставит жадно, ничего не продаёт), так что человек играет лучше, но относительную силу стратегий видно.
- **20-я волна — стена:** у узурпатора около 43 тысяч здоровья (здоровье врагов растёт до ×29 к 20-й волне). Ни одна стратегия бота её не проходит.
- **Тесты-сторожа** в `test/bot.test.ts`: одни баллисты должны быть слабее смешанной стратегии без баллист, а баллиста III — не больше чем на 25% выгоднее баллисты I. Упал сторож — не обязательно ошибка: если так и задумано, поправь порог.

## Как проверять в браузере

`npm run e2e` собирает игру, сам поднимает `vite preview` и открывает её в Chrome без окна через `playwright-core`. Скрипт — `apps/web/e2e/smoke.mjs`. Состояние игры он читает через `window.__throne` (есть только с `?debug`), а результат печатает списком «✓ / ✗». Нужен установленный Google Chrome; если его нет — `npx playwright install chromium`.

Что проверяется (32 пункта):
- шрифты загрузились, фокус стоит на «Играть», подсказка для новичка;
- постройка мышью, карточка магазина нажата;
- панель башни («Лучник I», «урон 9 → 15 | дальность 2,3 → 2,5»), улучшение, тост «не хватает золота», продажа за 60%;
- постройка с клавиатуры: 1, стрелки, Enter;
- пробел начинает волну, кнопка «Идёт бой», скорость ×3, первая волна отбита без потерь, превью следующей волны;
- пауза останавливает время;
- поражение: экран, сохранение рекорда, «Это ваш новый рекорд», «Сыграть ещё раз»;
- победа (через `?debug` перескок на 20-ю волну) и бесконечный режим;
- баллиста показывает числа баланса v2;
- зажатый пробел не ставит паузу; испорченный рекорд не ломает меню;
- телефон 390×844: постройка касанием;
- нет ошибок в консоли.

Подсказка для новых проверок: пробел на кнопке в фокусе нажимает саму кнопку. Перед проверкой пробела снимай фокус (`blur` в скрипте), `body.focus()` для этого не подходит.

## Приложения

### A. Фаервол

```bash
sudo ufw allow OpenSSH        # СНАЧАЛА SSH, иначе потеряешь доступ к серверу
sudo ufw allow 'Nginx Full'   # 80 и 443
sudo ufw enable
sudo ufw status
```

### B. Конфиг nginx

Файл `/etc/nginx/sites-available/throne-defense`:

```nginx
server {
    listen 80;
    server_name throne-defense.ru www.throne-defense.ru;

    root /var/www/throne-defense;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

- `try_files … /index.html` — если запрошенного файла нет, nginx отдаёт `index.html`. Нужно для режима history во Vue Router.
- `location /api/` — запросы `/api/...` уходят в Node. Пока бэкенда нет, они будут отвечать ошибкой 502, это нормально.

Включение:

```bash
sudo apt install nginx certbot python3-certbot-nginx
sudo mkdir -p /var/www/throne-defense
sudo ln -s /etc/nginx/sites-available/throne-defense /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

### C. HTTPS через certbot

Certbot получает бесплатный сертификат Let's Encrypt, прописывает его в конфиг nginx и сам продлевает. Запускать **после** того, как DNS указывает на VPS: Let's Encrypt проверяет домен через порт 80.

```bash
sudo certbot --nginx -d throne-defense.ru -d www.throne-defense.ru
sudo certbot renew --dry-run   # проверка автопродления
```

### D. Выложить игру вручную (до этапа 2)

На сервер едет не исходный код, а собранная игра — папка `apps/web/dist/`:

```bash
npm run build
rsync -av --delete apps/web/dist/ <логин>@77.91.113.61:/var/www/throne-defense/
```

- `/` в конце `dist/` означает «содержимое папки», а не саму папку.
- `--delete` удаляет на сервере файлы, которых больше нет в сборке (старые `index-XXXX.js`).

Если не хватает прав, сначала на сервере: `sudo chown <логин> /var/www/throne-defense`.
