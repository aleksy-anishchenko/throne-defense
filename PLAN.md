## Правила работы

1. **После каждого шага игра работает** и `npm run check` зелёный. Для изменений в интерфейсе или игре — ещё `npm run e2e`. Новое поведение — новая проверка в `apps/web/e2e/smoke.mjs`.
2. Маленькие коммиты с понятными сообщениями.
3. **Всё, что попало в `main`, само уезжает на сервер.** Крупное делаем в отдельной ветке (`check.yml` проверяет каждый пуш) и сливаем, когда всё зелёное.
4. **Секреты не коммитим.** На сервере они в `.env`, для Actions — в GitHub Secrets.
5. Баланс меняем только с проверкой: `npm run towers`, `npm run balance`, `npm test`. После правки чисел поднимаем `BALANCE_VERSION` и пишем в комментарии, что поменяли.
6. Не ломаем то, что уже хорошо: фиксированный шаг симуляции, клавиатуру, aria-атрибуты, `prefers-reduced-motion` и всё из [«Подводных камней»](#подводные-камни-не-ломать).
7. **Переименования и перестановки не меняют поведение.** Проверка: вывод `npm run towers` и `npm run balance` до и после совпадает до символа (кроме «за N мс»). ⚠️ Рисование так не проверить: после правок в `apps/web/src/render/` посмотри волну глазами.
8. **Команды на сервере выполняет владелец сам** и присылает вывод. Claude по SSH не ходит: даёт команды небольшими порциями с объяснением. Настройки сервера — файлами в `deploy/`, на сервер копируем (`scp`), а не правим на месте.

### Как называем вещи в коде

Имена — полные английские слова. Комментарии — по-русски, объясняют «почему».

| Понятие | Пишем | Не пишем |
|---|---|---|
| Клетка поля | `cell`, `col`, `row` | `c`, `r`, `tile` |
| Радиус | `radius` | `r` |
| Ступень башни (с нуля) | `tier`, `def.tiers` | `lv`, `level` |
| Карта | `level` (`LevelDef`) | — |
| Урон | `damage`, `damageKind` | `dmg` |
| Пауза между выстрелами | `cooldown`, `cooldownLeft` | `rate`, `cd` |
| Да/нет | `isDead`, `isPaused`, `isMuted`, `isReady` | `dead`, `on`, `ok` |
| Переменная цикла | `enemy`, `tower`, `shot` | `e`, `t`, `s` |

- Оставляем общепринятые: `x`, `y`, `i`, `id`, `dt`, `hp`, `ctx` (только canvas), `def`, `cols`/`rows`.
- Число «из воздуха» в формуле — в именованную константу с комментарием. Числа баланса остаются данными в `data/*.ts`, координаты рисунков — в `render/`.
- Хитрые однострочники разворачиваем. CSS-классы — словами (`.card-name`).
- Не переименовываем то, от чего зависят данные игроков и инструменты: ключи `localStorage`, формат рекорда `{ score, wave }`, `window.__throne`, id башен и врагов, названия событий, npm-скрипты.

## Роли башен: настройка (в работе)

Цель: у каждой башни своя роль, роли не пересекаются, ни одна башня не «лучше всех против всего». Решение владельца 14.11.2026: **сначала балансим девять имеющихся башен, новые — потом** (и скорее ветками улучшений, этап 6). Не хватает башне роли — сначала думаем о новом **враге** (роли рождаются из угроз: чародей из этапа 6 дал бы Огневику слабость).

**Мягкие контры, а не «одна башня — один враг».** Правильная башня против врага лучше в 1,5–2 раза, но не единственный ответ — иначе игра превращается в головоломку с одним решением. Две башни на одну угрозу — нормально, если работают по-разному (Пушкарь и Огневик — обе против толпы: издалека физикой и вблизи огнём, который ссорится со льдом).

**Правила (сделать тестами):**
1. У каждой башни есть враг, где она в первой двойке, и враг, где она в последней тройке.
2. Ни одна башня не в первой двойке больше чем против двух врагов.
3. Лучший против врага сильнее среднего в 1,5–2 раза, не в 10.
4. Стратегия из одной башни слабее «Смешанной» минимум на 2 волны.

**Угрозы врагов и задуманные ответы:** лазутчик — скорость (Лучник, прорвавшихся — Ловчий); бунтовщики и змеёныши — толпа (Пушкарь, Огневик); латник — броня (Огневик, Баллиста); знахарь — лечение; огр, Горыныч, узурпатор — много здоровья (Баллиста, Колдун). Поддержка: Морозко — «все вокруг медленнее», Ловчий — «поймать быстрых», Колдун — «гиганты получают больше», Звонарь — «соседи стреляют чаще», Казна — экономика.

**Что было не так (замеры 14.11.2026, v6):** Пушкарь отбросом залез в контроль и держал врагов у двери вечно (исправлено в v7); Баллиста хороша против всех («Только баллисты» = «Смешанная»); у Лучника нет врага, где он лучший (против лазутчиков слабее Баллисты I); Ловчий самый слабый; Звонарь и Казна почти ничего не добавляют боту.

- [x] **Пушкарь без отброса** — баланс v7, ветка `balance-v7-cannon` (см. [«Баланс»](#баланс-что-известно))
- [ ] **Таблица «башня × враг» без перебора урона** в `tools/balance`: настоящие враги со здоровьем волны N, считаем только снятое здоровье (`npm run towers` берёт бессмертных — переоценивает тяжёлые выстрелы: удар 210 по лазутчику с 98 здоровья засчитан целиком). Потоки: редкие бунтовщики (пауза 0,7 с), густая толпа (0,2 с), лазутчики, латники, огры. Плюс тесты на правила 1–4. Черновик скрипта был в `/tmp`, переписать начисто
- [ ] **Баллиста:** убрать универсальность — сильна против гигантов, слаба против мелких и быстрых
- [ ] **Лучник:** сильная сторона — лазутчики
- [ ] **Ловчий, Звонарь, Казна:** подтянуть числа, механику не трогать (Казна окупается ~7 волн — цель ~4)
- [ ] Живая игра; после неё — нужен ли чародей (враг, которого магия почти не берёт)

Порядок работы: одна башня за раз, после каждой — таблица и бот, новая `BALANCE_VERSION`. Бот считает целыми волнами — для тонкой настройки смотреть и счёт (он растёт с каждым убитым).

## Этап 5. Защита от читов (когда понадобится)

Счёт считается в браузере и подделывается. Для друзей терпимо; если станет важно:

- [ ] В состоянии игры — целый номер шага `tick`, время = `tick × шаг` (сейчас дробное, копит погрешность). ⚠️ Сверить вывод `npm run towers` и `npm run balance` до и после
- [ ] Действия игрока — данные: `{ tick, type: 'build', towerId, col, row }`. Игра применяет их одной функцией и ведёт журнал; `build`, `sell`… остаются тонкими обёртками
- [ ] Пауза, скорость и накопитель реального времени переезжают из логики в браузер
- [ ] На сервер уходит список действий; сервер прогоняет `packages/game` и сам считает счёт
- [ ] Случайность (если понадобится) — только генератор с зерном, одинаковый в браузере и на сервере

Основа есть: в логике нет случайности, одинаковые действия дают одинаковое состояние (тест с журналом событий), аргументы методов проверяются.

**Готово, когда:** результат с подделанным счётом сервер не принимает.

**Как игра и Vue общаются:**
- **Vue → игра:** кнопки вызывают методы (`game.build('archer', 5, 11)`, `game.startWave()`).
- **Игра → Vue:** события (`game.on('kill', …)`, `leak`, `victory`, `defeat`…). Подписаны стор (звук, экраны) и `render/effects.ts`.
- **Числа для интерфейса:** каждый кадр `useGameLoop`: `game.advance(dt)` → `renderer.draw()` → `store.syncHud()` (копирует золото, жизни, волну в реактивный `store.hud`) → `selection.sync()` (то же для выбранной башни: `selection.selected`).

## Кто кого может импортировать (обратно нельзя)

1. `packages/game` не импортирует ничего: ни Vue, ни DOM, ни Node. Нет `Math.random` и `Date`.
2. В `@throne/game` заходим только через `index.ts` (тестам самого пакета можно).
3. `render/` не знает про Vue, Pinia и стор: получает игру и `BoardView` аргументами.
4. `stores/` не импортирует компоненты. `audio/` не импортирует стор. `selection` знает про `game`, а `game` про `selection` — нет: сброс выбора при новой партии (`runCount`) и начале волны сделан через `watch` внутри `selection.ts`.
5. Сайт и сервер не импортируют друг друга; общее — в `game` и `contracts`.

Охраняется само: пункт 2 — `exports` в `packages/game/package.json`; пункт 1 (DOM, Node) — `tsconfig` пакета; `Math.random`/`Date`, `vue`/`pinia` в логике и пункт 3 — `eslint.config.js`.

**Чего не делать:** отдельные пакеты `shared`/`ui`/`utils`; деление `game` на «движок» и «контент»; пять-шесть Pinia-сторов (хватит двух); Nx, Turborepo, слои domain/application, шина событий поверх `game.on`.

В планах: `core/commands.ts` и `replay.ts` (этап 5).

## API и база

Адреса и схемы — `packages/contracts` (TypeBox): Fastify сам отвечает 400 на всё не по схеме.

| Адрес | Что |
|---|---|
| `GET /api/health` | `{ ok: true }`, проверяет базу; по нему автодеплой понимает, что API поднялось |
| `POST /api/runs` | `{ playerName, levelId, score, wavesCleared, balanceVersion }` → `{ rank, playerCount }` |
| `GET /api/leaderboard` | 10 лучших `{ entries, playerCount }` по всем залам и версиям; `?level=…` и `?balance=…` сужают |

- **Таблица** (`services/leaderboard.ts`): одно имя — одна строка с лучшим результатом (решение владельца); равные счета делят место, выше — кто набрал раньше. Игра спрашивает общую таблицу: все залы и все версии баланса вместе (решение владельца — результаты всегда остаются). Версия хранится у каждой партии, отобрать одну — `?balance=N`. Присылать результаты можно только текущей версии (иначе 422 — у игрока старая страница).
- **Имя** (`player-name.ts`): 1–20 символов, без невидимых, пробелы по краям убираются; ключ `localStorage` — `throne-name`. Результат уходит сам после каждой партии со счётом > 0.
- **Защита:** 60 запросов/мин с адреса, для `POST /api/runs` — 10. Адрес берётся из `X-Forwarded-For` только от nginx (`trustProxy: '127.0.0.1'`). **Правдоподобие** (`plausibility.ts`, ответ 422): уровень существует, версия баланса текущая, волн ≤ 100, счёт ≤ `maxPossibleScore`. Настоящая защита — [этап 5](#этап-5-защита-от-читов-когда-понадобится).
- **Мусор из топа** удаляем скриптом `src/scripts/delete-runs.ts` (инструкция в начале файла; сначала показывает, что удалит).
- **Без сервера** запросы ждут ≤ 5 с и возвращают `null`, не бросая ошибок.
- **База** — SQLite, WAL, таблица `runs`. На сервере `/srv/throne-defense/data/throne.db`, у себя `apps/server/data/`. Миграции применяются при запуске; номер последней — в `PRAGMA user_version`. **Применённую миграцию не правим** — только новый файл со следующим номером. База новее кода → сервер не стартует (так задумано).

## Подводные камни (не ломать)

- **Игра не реактивна.** Объект игры в `markRaw`; врагов в `ref`/`reactive` не класть — Vue будет следить за каждым 60 раз в секунду. Интерфейсу хватает `store.hud`.
- **В `packages/game` нет браузера** (в `tsconfig` нет `DOM`). Звук, эффекты, рекорд — только в `apps/web`.
- **Импорты внутри `game`, `contracts`, `server` — с расширением `.ts`** (`allowImportingTsExtensions`, `erasableSyntaxOnly`: нельзя `enum` и `namespace`). Так Node 24 выполняет TS без сборки.
- **Методы игры не верят аргументам:** клетки только целые, id проверяются через `Object.hasOwn`, `NaN` в `setSpeed`/`advance` пропускается, один `advance` — не больше 60 шагов. Важно для сервера.
- **В логике нет случайности** (`Math.random` — только в рисовании); ESLint следит.
- **Новые поля состояния — «плоские»:** числа, строки, id, без ссылок на объекты.
- **Горыныч распадается в конце шага:** погибший кладёт осколки в `state.splitQueue`, `spawnSplits` выпускает их после выстрелов (иначе тот же взрыв заденет змеёнышей). `spawnSplits` стоит до проверки конца волны.
- **Шаг симуляции — 1/60 с.** `advance(realDt)` копит время; `step()` ничего не делает вне фаз `build`/`wave`.
- **Скорость (×1/×2/×3) сохраняется** при «Сыграть ещё раз» (есть тест).
- **Ключи `localStorage`:** `throne-best` (`{ score, wave }`, читается через `parseBest`, перед сравнением перечитывается; счёт 0 — не рекорд), `throne-audio`, `throne-name`, старый `throne-muted` (`'1'` — звук выключен; читается, только пока нет `throne-audio`).
- **Постройка — один сценарий:** карточка стража → нажатие на свободную плиту. После постройки страж из «руки» убирается (`selection.tapCell`); на дорогого стража без золота карточка не берётся в руку — сразу тост и звук отказа (если золото упало уже после выбора — остаётся, откажет нажатие на плиту). Shift (мышь и Enter) оставляет его, чтобы ставить подряд. Нажатие на плиту без стража ничего не делает; начало волны и новая партия снимают выбор. Подсказка «страж в руке» выше подсказки паузы. Состояния «выбрана пустая плита» больше нет — не возвращать: оно путало (поставил не туда).
- **Клавиатура:** повторы зажатой клавиши игнорируются, кроме стрелок (иначе пробел начинал волну и ставил паузу). Порядок проверок в `useKeyboard.ts` менять осторожно. Клавиши не работают, пока фокус в поле ввода и открыты «Настройки» — кроме Escape.
- **После щелчка по кнопке фокус с неё снимается** (`onClick` в `useKeyboard.ts`), чтобы пробел шёл в игру, а не нажимал кнопку. С клавиатуры (`detail === 0`) фокус остаётся.
- **Боковая панель (раскладка «справа»)** включается, если `(min-width: 640px) and (min-aspect-ratio: 1/1)` **или** `(min-width: 940px) and (min-aspect-ratio: 9/10)`. Второе — широкое окно чуть выше своей ширины (983×987): по бокам поля пусто, панель сбоку даёт поле на ~14% крупнее; планшеты вертикально (768×1024, 820×1180) остаются с нижней панелью. Условие стоит в `styles/responsive.css` (первый запрос и запрос `max-height: 1150px`; запросы 760px и 560px — для низких экранов, широкое окно их не касается) и в `utils/layout.ts`; тест `layout.test.ts` следит, чтобы CSS и JS не разошлись. Без панели — `max-width: 639px`. Меняешь условие — меняй везде и проверяй `npm run e2e` (1280×860, 1366×650, 983×987, 768×1024, 390×844, 320×568, 932×430). С боковой панелью магазин (карточки `.shop`) стоит в самом верху панели, подсказка под ним; панель выбранной башни (`.tower-info`) занимает место магазина.
- **Телефон вертикально (без боковой панели): подсказка и одна строка кнопок.** `[кнопка][Начать волну][×1][⏸][⚙]`, панель ~86 px (на 320×568 поле на 32% крупнее, чем с девятью карточками). Кнопка слева (`ShopToggle.vue`) — всегда «Стражи» → меню выбора стража; страж в руке → на кнопке его значок. Меню башни своей кнопки не имеет: нажал на башню — оно открывается сразу; закрыл (крестик, мимо, Escape) — выбор с башни снят (выбранная башня без меню на телефоне ничего не даёт). Раньше был промежуточный шаг — кнопка «Действие»; убрана как лишняя. Кнопка всегда одного размера (118 px: значок + подпись) — строка не прыгает. «Начать волну» и значки справа мельче (40 px), чтобы хватило места. Когда ряд уже ≈360 px (`@container controls`: меряется ширина самой строки) у кнопки остаётся только значок 48 px (`aria-label` есть). Карточки `.shop` и панель `.tower-info` на телефоне скрыты.
- **Меню телефона** — парящие карточки с отступами от краёв (нижний ≥ 28 px; справа у списка место под полосу прокрутки, `scrollbar-gutter`). `ShopSheet.vue`: все стражи с описанием, характеристиками ступени I, ценой и «не хватает N». `TowerSheet.vue`: название, характеристики, цель, «Улучшить», «Вернуть», ✕ (без описания — оно в строке подсказки; перехода к постройке из него нет — решение владельца); сверху, если башня в нижней половине поля, чтобы не закрывать её. Выбрал стража — меню закрылось, осталось нажать на плиту. Esc или нажатие мимо закрывает меню: у меню стражей страж «в руке» остаётся, у меню башни снимается и выбор башни (`selection.closeMenu`). Меню башни открывает сам `tapCell` — только в телефонной раскладке (`isPhoneLayout` по `SIDE_PANEL_QUERY`): на компьютере открытое невидимое меню отключило бы клавиши. Состояние — `selection.openMenu` (`'shop' | 'tower' | null`); пока меню открыто, клавиши кроме цифр и Esc отключены; смена раскладки — `selection.syncMenuWithLayout` (появилась боковая панель — меню закрыто, выбор остаётся; пропала — у выбранной башни открывается меню). Меню модальное: Tab не выходит из него, при открытии с клавиатуры фокус возвращается на кнопку (`useMenuFocus.ts`; после щелчка мышью не возвращается — иначе пробел нажимал бы кнопку). Данные выбранной башни — `useSelectedTowerInfo.ts`, форматирование характеристик — `utils/towerStats.ts`.
- **«Фантомный щелчок» на телефоне.** Поле реагирует на `pointerdown`, и меню башни появляется, пока палец ещё на экране. После касания браузер шлёт `click`, и Safari на iPhone отправляет его в то, что под пальцем теперь, — в затемнение меню, которое его закрывало. Две защиты, не убирать: `@touchend.prevent` на canvas (`GameBoard.vue`) и затемнение `TowerSheet.vue` закрывает меню, только если на нём был и `pointerdown`. Chrome так не делает, поэтому e2e воспроизводит это `dispatchEvent('click')` по затемнению. Новый всплывающий слой, появляющийся по нажатию на поле, — та же ловушка.
- **Пустых полос внутри экрана нет.** Поле на телефоне упирается в ширину, лишняя высота делится пополам и становится внешними полями сверху и снизу всего интерфейса (`--board-slack` в `#app`, считает `fitBoard` в `useGameLoop.ts`; с боковой панелью не делится). Шапка, поле, подсказка и кнопки — один блок по центру.
- **Правило «кнопка или карточки»:** меню — только без боковой панели, где панель стоит под полем и съедает его высоту; с боковой панелью она отдельная колонка, поле не отнимает, и карточки остаются.
- **Всё в `.panel` стоит в колонке 1** (`.panel > *` в `layout.css`), иначе блоки, делящие ячейки сетки, уедут в неявную вторую колонку.
- **Минимальный экран — 320 px по ширине** (решение владельца). Уже 320 px раскладку не подгоняем: нижний ряд кнопок на 300 px не помещается, и это нормально.
- **Курсор над полем** — рука только там, где нажатие что-то делает (башня под мышью или свободная плита при страже в руке): `selection.isBoardClickable`, считается каждый кадр в `sync` (игра не реактивна, `computed` не заметил бы изменений).
- **Максимальная дальность:** у призрака стража «в руке» под обычным кругом рисуется бледный частый пунктир с дальностью высшей ступени (`drawRange(..., maxRange)` в `render/renderer.ts`); у уже стоящей башни — только текущая дальность (решение владельца). Не рисуется, если дальность не растёт (Казна). Цвет повторяет основной круг: золотой, при нехватке золота красный. Виден только при наведении мыши — на телефоне призрака нет.
- **Поле не перерисовывается, если ничего не поменялось.** `frameFingerprint` в `render/renderer.ts` (время, фаза, золото, жизни, число башен/врагов/снарядов, выбор игрока). Добавляешь то, что меняет картинку без изменения этих данных, — добавь в отпечаток, иначе картинка застынет.
- **Экран поверх поля — диалог:** шапка, поле и панель получают `inert` (`App.vue`). После поражения/победы фокус на сам экран (иначе Enter перезапустит партию), в меню — на «Играть».
- **TypeBox не должен попасть в игру.** Схемы нужны только серверу; сайту — файлы без TypeBox (`paths.ts`, `player-name.ts`), `"sideEffects": false` в `contracts`. Новое для сайта клади туда, иначе +~18 КБ gzip. Проверка: размер `index-….js` в `npm run build` (≈ 56 КБ gzip).
- **Новая `BALANCE_VERSION` таблицу лучших не обнуляет** (решение владельца: «результаты всегда остаются»). Сервер принимает партии только текущей версии (старая страница — 422 «обновите»), а показывает все версии вместе; одну — `?balance=N`. Раньше игра спрашивала только текущую версию, и после выкладки v6 таблица выглядела пустой — партии при этом лежали в базе. Если меняешь начисление очков (`SCORE`, `finishWave`, `loseHp`) — проверь `maxPossibleScore`: тест «ни одна стратегия бота не набирает больше» в `tools/balance/bot.test.ts`.
- **`smoke.mjs` — обычный JS, типы его не проверяют:** переименовал поле состояния или CSS-класс — ищи старое имя там руками.
- **Необязательное «да/нет»:** `undefined !== false` — истина. Приводи сначала (`art.drawOnTop ?? false`). Однажды пропали все враги кроме босса; теперь есть проверка «враг нарисован на поле».
- **Колонки экранов поверх поля — `grid-template-columns: minmax(0, 1fr)`** (`.overlay`, `.sheet`, `.name-form`), иначе поле имени раздвигает экран шире телефона 320 px. Минимум размера заголовка — 2rem.
- **Имя игрока** приводится к NFC; пустые на вид символы и «залго» (3+ надстрочных подряд) не проходят. Поле ввода ограничено 40 половинками UTF-16 (эмодзи — две).
- **Сервер не принимает партии с 0 очков.**

### Сознательно оставлено как есть (не «исправлять»)

- **Перезарядка округляется вверх до шага 1/60 с** — башни стреляют до ~3% реже, чем в `cooldown`. Баланс настроен с этим.
- **Замедление: сила и длительность обновляются по отдельности** (слабый долгий Морозко продлевает сильное). Баланс настроен с этим.
- **Огненный шар взрывается там, где цель была в последний раз**, даже если она погибла.
- **Разблокировка звука висит на каждом клике навсегда** — Safari/iOS «усыпляют» звук, будить можно только по действию игрока.
- **Отмена в «Поделиться» возвращает `'shared'`** — интерфейс реагирует только на `'copied'`.
- **Продажа без подтверждения.** Золото, вложенное между волнами (`tower.goldSinceLastWave`), возвращается целиком (кнопка «Вернуть»), остальное — 60%. Построенная/улучшенная во время волны башня сразу в бою — полного возврата нет.
- **`?debug` работает и в собранной версии** — на нём держится `npm run e2e`.
- **Номера врагов и башен после «Сыграть ещё раз» начинаются заново** — нужно для повторного прогона на сервере.
- **Цифры 1–9 читаются по положению клавиши** (`event.code`: `Digit`/`Numpad`), поэтому работают и с Shift (режим «ставить подряд»), и на любой раскладке.
- **`npm run check` проверяет типы интерфейса дважды** (`typecheck` и `build`) — зато сборку нельзя запустить без проверки типов.
- **`npm audit`** показывает записи средней тяжести из `minimatch` в зависимостях ESLint; в игру он не попадает. Перепроверить после обновления.

## Звук и музыка

Аудиофайлов нет: браузер синтезирует всё WebAudio. Код — `apps/web/src/audio/`.

- **`engine.ts`** — один `AudioContext` и настройки (`AudioSettings` в `utils/storage.ts`: выключатель и громкость 0–100% для звуков и музыки). Две «шины» громкости; громкость ползунка возводится в квадрат. Контекст создаётся только после действия игрока (`unlock()`).
- **`music.ts`** — мелодия в ля миноре на «гуслях» (8 тактов по кругу, ноты текстом `'E4 - A4 - B4 - C5 -'`) и слои по настроению: `calm` (меню, строительство), `battle` (волна), `danger` (Горыныч или узурпатор в волне), `silent` (победа/поражение). Настроение меняется на начале такта. **Ноты ставятся заранее по `context.currentTime`** (`setTimeout` раз в 25 мс смотрит на 0,15 с вперёд): играть прямо по таймеру нельзя — ритм «поплывёт». Темп от скорости игры не зависит.
- **`gameSounds.ts`** — подписки на события игры и `musicMoodFor`; стор следит (`watch`) за фазой, волной и паузой.
- **Пауза** глушит музыку фильтром, а не останавливает; в «Настройках» не глушит (игрок подбирает громкость). Свёрнутая вкладка — тишина.
- **«Настройки» посреди волны** ставят паузу и сами снимают её при закрытии (если паузу не поставил игрок до этого).

Решения владельца: отдельной кнопки музыки нет (на телефоне 320 px не хватает места — вместо «Звук» шестерёнка «Настройки»); музыка по умолчанию 70% (0,55 было громко); кнопки на экранах поверх поля — столбиком: Играть → Лучшие результаты → Настройки.

Проверить на слух: `npm run dev`; тревожную музыку быстро — `?debug`, в консоли `__throne.game.state.wave = 10`, «Начать волну». В e2e состояние музыки читается через `window.__throne.music.debugState()` (как звучит — проверки не знают). ⚠️ В меню две кнопки «Настройки» (шестерёнка тоже в разметке, хоть и `inert`) — в проверках ищи внутри `getByRole('dialog')`.

## Как проверять в браузере

`npm run e2e` собирает игру, поднимает `vite preview` и настоящий API на временной базе (порт 3101), открывает Chrome без окна через `playwright-core` и печатает список «✓ / ✗». Состояние читает через `window.__throne` (только с `?debug`). Последний сценарий — «без сервера»: там (только там) ошибки «Failed to load resource» ожидаемы. Нужен Google Chrome (иначе `npx playwright-core install chromium`); в Actions он есть.

Числа баланса в скрипте зашиты намеренно: поменял баланс — обнови их вместе с `BALANCE_VERSION`. На картинку смотрит одна проверка — «враг нарисован на поле»; остальное в `render/` проверяй глазами (правило 7).

Подсказка: пробел на кнопке в фокусе нажимает саму кнопку. После `locator.focus()` или Tab снимай фокус перед проверкой пробела (`blurActiveElement` в скрипте; `body.focus()` не подходит).

## Словарик

- **DNS, A-запись, TTL** — «имя → адрес сервера» у регистратора; TTL — сколько секунд провайдеры помнят ответ.
- **nginx** — отдаёт файлы сайта и пересылает `/api` в Node.
- **certbot, Let's Encrypt** — бесплатный HTTPS-сертификат и программа, которая его продлевает.
- **rsync, rrsync** — копирование только изменившихся файлов; rrsync разрешает ключу только rsync в одну папку.
- **pm2** — перезапускает Node после падения и перезагрузки.
- **Миграции** — файлы, по шагам описывающие изменения структуры базы.
- **GitHub Actions, workflow, Secrets** — автозапуск команд на каждый пуш; файл с командами; хранилище паролей и ключей.
- **CORS** — запрет браузера ходить на чужой адрес; нам не нужен (один адрес).
- **Детерминированность** — одинаковые действия → одинаковый результат; без неё сервер не перепроверит партию.
- **tick, seed** — номер шага симуляции; начальное число генератора «случайных» чисел.
- **Прототип** — `TOWERS['constructor']` находит встроенную функцию, поэтому `Object.hasOwn(TOWERS, id)`.
- **inert, aria-modal** — выключают всё под экраном поверх страницы / сообщают об этом скринридеру.
