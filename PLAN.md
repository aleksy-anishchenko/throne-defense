# План проекта «Защита трона»

Рабочий документ с текущим состоянием, открытыми задачами и правилами разработки.
История изменений хранится в Git, история чисел — в `packages/game/src/data/balance.ts`.

## Текущее состояние

Актуально на 18 ноября 2026 года. Баланс v36.

- Игра содержит шесть компактных залов, девять стражей, 20 волн и бесконечный режим.
- После волн 5, 10, 15 и 19 игрок выбирает один из трёх бонусов. Всего доступно 12 бонусов.
  «Щедрая награда» и «Военный налог» предлагаются только после волн 5 и 10.
- Узурпатор не получает лечение. На 19-й волне четыре огра, 14 латников, три знахаря
  и два Горыныча; на 20-й волне два знахаря.
- Знахарь лечит не больше трёх наиболее раненых союзников за импульс и не лечит
  других знахарей. В бесконечном режиме одновременно выходит не больше шести знахарей.
- `npm run check` проходит: 388 тестов, форматирование, ESLint, типы и production-сборка.
  Browser E2E проходит на компьютере и телефоне.
- Полное прохождение всех 20 волн во всех залах в v36 вручную не подтверждено.

## Ближайшие задачи

### 1. Подтвердить игровой баланс

- [ ] Пройти 20 волн вручную во всех шести залах.
- [ ] Записать для каждого зала расстановку, остаток жизней и проблемы на волнах 15–20.
- [ ] Проверить, что все 12 бонусов дают осмысленный выбор хотя бы в одном архетипе.
- [ ] Проверить лечение знахарей и Колдуна в бесконечном режиме на волнах 30–50.
- [ ] По результатам менять один параметр баланса за раз и повторять полный набор проверок.

Цель: каждый зал проходим разумной стратегией, а финальные волны остаются сложными,
но не требуют одной заученной расстановки.

### 2. Упростить текст для игрока

- [ ] Переписать описания стражей как нейтральные описания их действий.
- [ ] Убрать из карточек советы и оценки: «хорош против», «слаб против», «используйте»,
  «не сочетайте».
- [ ] Оставить в карточке название, цену, одно короткое описание и характеристики.
- [ ] Показывать подробные взаимодействия только в выбранном страте, если без них нельзя
  понять механику.
- [ ] Использовать единые термины: «страж», «враг», «броня», «бонус», «специализация».
- [ ] Сократить описания бонусов до одного действия с числом.
- [ ] Убрать из интерфейса формулы, служебные правила сложения эффектов и повторяющиеся
  подсказки.
- [ ] Обновить e2e-проверки пользовательских текстов после изменений.

Критерий: игрок понимает назначение стража по описанию, но стратегия остаётся его выбором.

### 3. Защитить рейтинг

- [ ] **Достоверность результата:** сервер должен принимать рекорд только с проверенным
  журналом партии либо явно маркировать результат как непроверенный.
- [ ] **Идентичность игрока:** отделить `player_id` от отображаемого имени и исключить
  подмену чужих рекордов одноимённым игроком.
- [ ] **Идемпотентность:** добавить `runId` с ограничением уникальности, чтобы повторная
  отправка не создавала дубликаты.
- [ ] **Хранение:** определить срок хранения истории партий и хранить лучшие результаты
  отдельно от полной истории.

## Правила баланса

- Страж должен иметь собственную полезную роль, но без универсально лучшего выбора.
- Основные текущие проверки находятся в `packages/game/test` и
  `tools/balance/compact-roles.test.ts`.
- Любое изменение игровых чисел требует обновления `BALANCE_VERSION`.
- Изменение баланса проверяется через `npm run towers`, `npm run balance`, `npm run check`
  и ручную партию.
- Зелёные технические тесты не заменяют подтверждённое ручное прохождение.

## Устройство проекта

- `packages/game` — правила, данные баланса и уровни; чистый TypeScript без Vue и DOM.
- `apps/web` — Vue-интерфейс, Canvas-отрисовка, звук и клиент API.
- `apps/server` — Fastify API и SQLite.
- `packages/contracts` — общие схемы и типы API.
- `tools/balance` — симуляции ботов и измерения баланса.
- `deploy` — release-скрипты, nginx, pm2 и резервное копирование.
- `.github/workflows` — проверки и автоматическая выкладка.

## Рабочие правила

- Игровая логика остаётся детерминированной и не зависит от Vue, DOM и Node.
- Схемы API меняются согласованно в `packages/contracts`, клиенте и сервере.
- Секреты не коммитятся.
- Изменения интерфейса проверяются через `npm run e2e`.
- Перед публикацией выполняется `npm run check`.
- Изменения в `main` автоматически деплоятся на сервер.

## Команды

```bash
npm run dev             # веб-приложение
npm run dev:server      # API
npm run towers          # эффективность башен
npm run balance         # симуляция стратегий по залам
npm run balance:aspects # сравнение специализаций Баллисты
npm test                # тесты
npm run e2e             # браузерная проверка
npm run check           # форматирование, линтер, типы, тесты и сборка
```
