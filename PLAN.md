## Правила работы

1. **После каждого шага игра работает** и `npm run check` зелёный. Для изменений в интерфейсе или игре — ещё и `npm run e2e`. Новое поведение — новая проверка в `apps/web/e2e/smoke.mjs`.
2. Маленькие коммиты с понятными сообщениями. Крупный этап делаем в отдельной ветке и сливаем в `main`, когда всё проверено.
3. После этапа 2 всё, что попало в `main`, само уезжает на сервер. Поэтому в `main` — только рабочее.
4. **Секреты (пароли, токены, ключи) не коммитим никогда.** На сервере они лежат в `.env`, для Actions — в GitHub Secrets.
5. Баланс меняем только с проверкой: `npm run towers`, `npm run balance`, `npm test`. После любой правки чисел поднимаем `BALANCE_VERSION` и пишем в комментарии рядом, что поменяли.
6. Не теряем то, что уже хорошо: фиксированный шаг симуляции, управление с клавиатуры, aria-атрибуты, `prefers-reduced-motion`. И не ломаем то, что перечислено в [«Подводных камнях»](#подводные-камни-не-ломать).
7. **Переименования и перестановки кода не меняют поведение.** Логика детерминированная, поэтому проверка простая: вывод `npm run towers` до и после совпадает до символа, вывод `npm run balance` — тоже (кроме времени «за N мс»). Любое расхождение — нечаянно изменённая формула. ⚠️ Рисование так не проверить: после правок в `apps/web/src/render/` запусти игру и посмотри волну глазами (почему — см. [итоги ревью](#итоги-код-ревью-12-ноября-2026)).
8. Если у владельца настроен вход на VPS по SSH-ключу, Claude может настроить сервер сам — нужно спросить логин и показывать каждую команду перед запуском.

### Как называем вещи в коде

Код пишем так, чтобы его можно было читать без подсказок. Имена — полные английские слова. Комментарии — по-русски и объясняют «почему», а не пересказывают код.

| Понятие | Пишем | Не пишем |
|---|---|---|
| Клетка поля: столбец и строка | `cell`, `col`, `row` | `c`, `r`, `tile` |
| Радиус | `radius` | `r` |
| Ступень улучшения башни (с нуля: 0 — это «I») | `tier`, `def.tiers` | `lv`, `level` |
| Карта | `level` (`LevelDef`, `game.level`) | — |
| Урон и вид урона | `damage`, `damageKind` | `dmg` |
| Пауза между выстрелами и сколько её осталось | `cooldown`, `cooldownLeft` | `rate`, `cd` |
| Да/нет | `isDead`, `isPaused`, `isMuted`, `isReady` | `dead`, `on`, `ok` |
| Переменная в цикле или стрелочной функции | `enemy`, `tower`, `shot` | `e`, `t`, `s` |

- Короткие имена, которые оставляем, потому что их знают все: `x`, `y`, `i`, `id`, `dt` (шаг времени), `hp`, `ctx` (только контекст canvas), `def` (описание: `tower.def`), `cols`/`rows`.
- Число «из воздуха» посреди формулы выносим в константу с именем и комментарием: `LINE_SHOT_HIT_MARGIN = 0.1`, а не просто `0.1`. Числа баланса остаются данными в `data/*.ts`, координаты рисунков — в `render/`.
- Хитрые однострочники разворачиваем: вложенные тернарные операторы, `;(a ?? b)(x)`, `a = b = c`, `if (--count <= 0)`.
- CSS-классы — тоже словами: `.card-name`, а не `.nm`.
- Не переименовываем то, от чего зависят данные игроков и инструменты: ключи `localStorage` и формат рекорда `{ score, wave }`, `window.__throne`, id башен и врагов, названия событий игры, npm-скрипты.

## Итоги код-ревью (12 ноября 2026)

Как проверяли: весь код прочитали 7 независимых ревьюеров. Каждую находку потом пытался опровергнуть другой проверяющий — читал код заново, запускал скрипты и собранную игру в Chrome. Из 91 находки **15 подтвердились полностью, 60 — частично** (проблема есть, но мельче, чем казалось, или важна только для будущего сервера), **16 опровергнуты**.

Общая оценка: код в хорошем состоянии, серьёзных ошибок в правилах игры нет.

| Зона | Вывод |
|---|---|
| Логика (`packages/game`) | Правила считаются верно; при 60 и при 6 кадрах в секунду результат одинаков. Слабое место — публичные методы верят любым аргументам. Игроку это не грозит, но станет дырой, когда партии будет проверять сервер (этапы 3 и 5) |
| Данные и тесты | Данные согласованы, цифры в этом документе совпали с выводом `npm run towers` и `npm run balance`. Тестам не хватает проверок на целостность данных и на точность хода времени |
| Интерфейс и раскладка | **Главная находка:** на телефоне, повёрнутом набок, кнопка «Начать волну» уезжает за край экрана. Постройка и продажа работают верно; есть мелочи по доступности и то, что правая кнопка мыши тоже ставит башню |
| Производительность | Оптимизировать нечего. Шаг симуляции занимает около 0,06 мс при бюджете 5,5 мс, кадр — 1,4–1,8 мс (3,2 мс на медленном телефоне), память в бесконечном режиме не растёт |
| Сборка | Быстрая и лёгкая (JS 116 КБ, около 45 КБ в сжатом виде). В папку `dist` попадают лишние шрифты |

В инструкциях по серверу (приложения A–D) тоже нашлись ошибки — они исправлены прямо в приложениях.

**Чистка кода.** Имена приведены к правилам из раздела выше, поведение не менялось. Проверено сравнением «старый код против нового»: 800 случайных партий (17,6 млн шагов симуляции) дали одинаковое состояние до последнего числа, а 82 кадра в Chrome совпали по пикселям, DOM и раскладке.

Урок этой проверки: при переименовании одна строка в `renderer.ts` потеряла приведение к «да/нет», и обычные враги перестали рисоваться — на поле остался бы только босс. Ни 50 тестов, ни 32 проверки в браузере этого не заметили: они смотрят на состояние игры и на разметку, а не на картинку. Поймало только сравнение по пикселям; ошибка исправлена. Отсюда оговорка в правиле 7 и проверка «враг нарисован на поле» в `smoke.mjs` (на той самой ошибке она краснеет).

## Этап 5. Защита от читов (когда понадобится)

Счёт сейчас считается в браузере, и его можно подделать. Для рейтинга среди друзей это терпимо, но если станет важно, делаем так:

- [ ] В состоянии игры появляется целый номер шага `tick`, а время считается как `tick × шаг`. Сейчас время — дробное число, которое копит погрешность, и привязать действие игрока к конкретному шагу нечем (ревью). ⚠️ Меняет значения времени в мелких знаках: сверить вывод `npm run towers` и `npm run balance` до и после
- [ ] Действия игрока становятся данными: `{ tick, type: 'build', towerId, col, row }`. Игра применяет их одной функцией и сама ведёт журнал. Старые методы (`build`, `sell`…) остаются тонкими обёртками
- [ ] Пауза, скорость и накопитель реального времени переезжают из логики игры в браузер: это «часы» конкретного игрока, а не правила, и в запись партии они попадать не должны
- [ ] На сервер отправляется список действий, а не счёт
- [ ] Сервер прогоняет ту же логику из `packages/game` и сам считает счёт
- [ ] Если в логике понадобится случайность — только генератор с зерном (seed), одинаковый в браузере и на сервере

Основа уже есть: в логике нет случайности, и одинаковые действия дают одинаковое состояние.

**Готово, когда:** результат с подделанным счётом сервер не принимает.

**Как игра и Vue общаются** (как родитель и ребёнок):
- **Vue → игра:** кнопки вызывают методы: `game.build('archer', 5, 11)`, `game.startWave()`…
- **Игра → Vue:** игра сообщает о событиях (`game.on('kill', …)`, `leak`, `victory`, `defeat`…). На них подписаны стор (звук, экраны, «подпрыгивания» в шапке) и `render/effects.ts` (искры, тряска).
- **Числа для интерфейса:** каждый кадр игровой цикл (`composables/useGameLoop.ts`) делает три вещи: `game.advance(dt)` → `renderer.draw()` → `store.syncHud()`. `syncHud()` копирует золото, жизни, волну и т.п. в реактивный объект `store.hud`.

## Куда движется структура

Границы уже проведены правильно: правила игры отдельно от интерфейса, рисование отдельно от Vue, наружу пакет смотрит через один `index.ts`. Новые пакеты и слои не нужны. Меняем только то, что мешает ближайшим этапам, и только тогда, когда этап до этого дошёл. Что появится:

```
deploy/                      (этап 1)  всё про сервер: nginx/, scripts/, позже pm2/
.github/workflows/           (этап 2)  check.yml, deploy.yml
packages/contracts/          (этап 3)  типы запросов и ответов API для сайта и сервера
apps/server/                 (этап 3)  src/routes, src/db, src/services
packages/game/src/core/      (этап 5)  + commands.ts и replay.ts: действия как данные
apps/web/src/stores/         (этап 6)  + selection.ts — выбор игрока, из game.ts
apps/web/src/audio/          (этап 6)  + gameSounds.ts — подписки на звук, из стора
apps/web/src/styles/         (этап 6)  вместо одного style.css
```

**Кто кого может импортировать** (обратно нельзя):

1. `packages/game` не импортирует ничего: ни Vue, ни DOM, ни Node. В нём нет `Math.random` и `Date`.
2. Снаружи в `@throne/game` заходим только через `index.ts`, не в глубину. Тестам самого пакета можно.
3. `render/` не знает про Vue, Pinia и стор: получает игру и `BoardView` аргументами.
4. `stores/` не импортирует компоненты. `audio/` не импортирует стор.
5. Сайт и сервер не импортируют друг друга. Общее лежит в `game` и `contracts`.

Что уже охраняется само: пункт 2 (поле `exports` в `packages/game/package.json`) и запрет на DOM и Node в пункте 1 (`tsconfig` пакета). `Math.random`/`Date` и импорт `vue`/`pinia` в логике, а также пункт 3 (импорт `vue`, `pinia` и стора в `render/`) ловит ESLint — правила в `eslint.config.js`.

**Чего не делать** (соблазнительно, но для проекта такого размера — лишнее):
- отдельные пакеты `shared`, `ui`, `utils`; деление `packages/game` на «движок» и «контент»;
- пять-шесть Pinia-сторов: состояния связаны (победа → рекорд → экран → звук), хватит двух;
- Nx, Turborepo, слои «domain/application/infrastructure», шина событий поверх `game.on`.

Отложено сознательно, хотя предлагалось: перенос `e2e/` в корень, разнос `src/types.ts` по папкам, номер шага `tick` «уже сейчас» (он меняет значения времени, поэтому ждёт этапа 5).

## Подводные камни (не ломать)

- **Игра не реактивна.** Объект игры обёрнут в `markRaw`. Если положить врагов в `ref`/`reactive`, Vue будет следить за каждым из них 60 раз в секунду, и игра начнёт тормозить. Интерфейсу хватает снимка `store.hud`.
- **В `packages/game` нет браузера.** В `tsconfig` нет `DOM`: если логика полезет в `document`, `window` или `localStorage`, TypeScript выдаст ошибку. Звук, эффекты, рекорд — только в `apps/web`.
- **Импорты внутри `packages/game` пишутся с расширением `.ts`** (`'./core/game.ts'`). Включены `allowImportingTsExtensions` и `erasableSyntaxOnly` (нельзя `enum` и `namespace`). Так Node 24 выполняет TypeScript напрямую, без сборки: на этом работают `npm run balance`/`towers`, и на этом же будет работать сервер.
- **В логике нет случайности** (`Math.random` только в рисовании: искры, покачивание). Это нужно для этапа 5.
- **Новые поля в состоянии игры — «плоские»:** числа, строки, id, без ссылок на другие объекты. Так состояние потом будет проще сохранить и сравнить (этапы 5 и 6).
- **Шаг симуляции фиксированный — 1/60 с.** `advance(realDt)` копит реальное время и делает нужное число шагов. `step()` ничего не делает вне фаз `build`/`wave`: раньше после поражения дошедший враг «доходил» снова на каждом шаге, на это есть тест.
- **Скорость (×1/×2/×3) сохраняется** при «Сыграть ещё раз», как в оригинале. На это есть тест.
- **Ключи `localStorage` — `throne-best` и `throne-muted`**, как в оригинальной игре, чтобы не потерять рекорды. Рекорд хранится как `{ score, wave }`, где `wave` — сколько волн отбито; эти имена менять нельзя. Рекорд читается через `parseBest`, который отбрасывает мусор: раньше испорченная запись роняла меню.
- **Клавиатура:** повторы от зажатой клавиши игнорируются, кроме стрелок. Иначе зажатый пробел начинал волну и тут же ставил паузу. Порядок проверок в `useKeyboard.ts` менять осторожно.
- **Боковая панель включается условием `(min-width: 640px) and (min-aspect-ratio: 1/1)`** (ширина от 640 и окно не выше, чем шире — это и телефон набок). Оно повторяется в двух media-запросах `style.css`: в основном и в компактном (`max-height: 560px`, телефон набок), а запрос для низкого экрана без панели написан как его противоположность (`max-width: 639px`). Меняешь одно — поменяй все три и проверь `npm run e2e` (там есть проверка «кнопка на экране» на 390×844 и 932×430).
- **Поле не перерисовывается, если ничего не поменялось.** `renderer.draw()` собирает «отпечаток» кадра (`frameFingerprint` в `render/renderer.ts`): игровое время, фаза, золото, жизни, число башен, врагов и снарядов, выбор игрока. Совпал с прошлым — кадр пропускается (в меню и на паузе 0 кадров в секунду вместо 60). Тряска и красная вспышка идут в реальном времени, пока они есть — рисуется всегда. Если добавляешь то, что меняет картинку **без** изменения этих данных (анимацию в реальном времени на паузе, новое поле состояния, которое видно на поле, не меняя золота и числа объектов), — добавь его в отпечаток, иначе картинка застынет.
- **Экран поверх поля — диалог.** Пока он открыт, шапка, поле и панель получают атрибут `inert` (в `App.vue`). После поражения и победы фокус ставится на сам экран, а не на кнопку — иначе Enter, нажатый в этот момент, перезапустит партию. В меню фокус на «Играть».
- **`smoke.mjs` — обычный JavaScript, типы его не проверяют.** Если переименовать поле состояния игры или CSS-класс, TypeScript промолчит: ищи старое имя в этом файле руками.
- **Необязательное поле «да/нет» сравнивай осторожно.** Незаданное поле (`drawOnTop?: boolean`) — это `undefined`, а `undefined !== false` — истина. Сначала приведи к «да/нет» (`art.drawOnTop ?? false`), потом сравнивай. На этом при чистке кода пропали с поля все враги, кроме босса.

### Сознательно оставлено как есть (не «исправлять»)

Эти места выглядят как ошибки, и код-ревью на них указывало, но так сделано специально:
- **Перезарядка башен округляется вверх до шага 1/60 с**, поэтому башни стреляют до ~3% реже, чем написано в `cooldown`. Так было в оригинале, и баланс настроен именно с этим. «Исправить» — значит сделать все башни сильнее, то есть поменять баланс.
- **Замедление: сила и длительность обновляются по отдельности.** Слабый, но долгий Морозко продлевает действие сильного. Так было в оригинале, баланс настроен с этим.
- **Огненный шар взрывается там, где цель была в последний раз**, даже если она уже погибла. Так задумано.
- **Разблокировка звука висит на каждом клике/нажатии навсегда.** Safari и iOS «усыпляют» звук после звонка или переключения приложений, а разбудить его можно только по действию игрока.
- **Отмена в меню «Поделиться» возвращает `'shared'`.** Интерфейс реагирует только на `'copied'`, так что разницы для игрока нет.
- **Продажа башни без подтверждения.** Как в оригинале и в большинстве игр жанра; возврат 60% сразу виден.
- **`?debug` работает и в собранной версии.** На нём держится `npm run e2e`. Взломать игру в браузере можно и без него; от подделки счёта защитит только проверка на сервере (этап 5).
- **Номера врагов и башен после «Сыграть ещё раз» начинаются заново** — для повторного прогона партии на сервере это как раз нужно.
- **Клавиши 1–9 читаются по символу, а не по положению клавиши:** на французской раскладке (AZERTY) не работают, но игра русскоязычная.
- **Бот ищет лучшую клетку, даже когда копит золото:** лишняя работа, но партия у бота считается за 20–80 мс.
- **`npm run check` проверяет типы интерфейса дважды** (в `typecheck` и в `build`). Потеря — секунды, зато сборку нельзя запустить без проверки типов.
- **`npm audit` показывает несколько записей средней тяжести с одним источником** — пакет `minimatch` в зависимостях ESLint. В игру он не попадает; перепроверить, когда выйдет обновление.

## Баланс: что известно

**Как меряем выгодность башни** (`npm run towers`): башня ставится на лучшую для неё клетку, мимо идёт поток врагов, которых нельзя убить, и весь урон делится на вложенное золото. Так учитываются сразу дальность, скорострельность, броня, пробивание и взрывы. Замер приблизительный: он не учитывает лишний урон по почти убитому врагу, рост здоровья врагов и то, как башни помогают друг другу.

**Версия 2** (что менялось — в комментарии к `BALANCE_VERSION` в `data/balance.ts`):
- Баллиста после ослабления: на первой ступени выгоднее лучника примерно в 1,5 раза (дорогая и слабая в начале), а улучшения почти не добавляют выгоды.
- Урон на монету против бунтовщиков, ступень I: лучник 9,5, огневик 10, Морозко 12, баллиста 13,8. Против латников огневик (12,4) намного лучше лучника (4,7).
- **Морозко** против толпы и латников наносит больше всех урона на монету (12–19 в зависимости от ступени), хотя в описании «сам почти не ранит». Морозко и лучник вместе наносят почти втрое больше, чем один лучник, — в основном за счёт урона самого Морозко, а не замедления. Боты с ним не доминируют, поэтому пока не трогали — проверить в живой игре.
- **Боты** (`npm run balance`): «Только лучники» падают на 14-й волне, «Только баллисты» и «Огонь и баллисты» — на 17-й, «Смешанная без баллист» — на 19-й, «Смешанная» доходит до 20-й и проигрывает узурпатору. Бот глупый (ставит жадно, ничего не продаёт), так что человек играет лучше, но относительную силу стратегий видно.
- **20-я волна — стена:** у узурпатора около 43 тысяч здоровья (здоровье врагов растёт до ×29 к 20-й волне). Ни одна стратегия бота её не проходит.
- **Тесты-сторожа** в `tools/balance/bot.test.ts`: одни баллисты должны быть слабее смешанной стратегии без баллист, а баллиста III — не больше чем на 25% выгоднее баллисты I. Упал сторож — не обязательно ошибка: если так и задумано, поправь порог.

## Как проверять в браузере

`npm run e2e` собирает игру, сам поднимает `vite preview` и открывает её в Chrome без окна через `playwright-core`. Скрипт — `apps/web/e2e/smoke.mjs`. Состояние игры он читает через `window.__throne` (есть только с `?debug`), а результат печатает списком из 45 строк «✓ / ✗» — по нему и видно, что проверяется. Нужен установленный Google Chrome; если его нет — `npx playwright-core install chromium`.

Числа баланса в скрипте зашиты намеренно (золото после покупок, «урон 9 → 15», «Дальше: 12 бунтовщиков»): поменял баланс — обнови их вместе с `BALANCE_VERSION`.

На картинку смотрит одна проверка — «враг нарисован на поле»: квадрат canvas вокруг врага с врагом и без него. Остальное в `render/` по-прежнему проверяй глазами (правило 7).

Подсказка для новых проверок: пробел на кнопке в фокусе нажимает саму кнопку. Перед проверкой пробела снимай фокус (`blurActiveElement` в скрипте), `body.focus()` для этого не подходит.

## Словарик

- **DNS, A-запись** — строчка у регистратора домена: «имя `throne-defense.ru` — это сервер с таким-то адресом».
- **nginx** — программа на сервере, которая отдаёт файлы сайта и пересылает запросы `/api` в Node.
- **certbot, Let's Encrypt** — бесплатный сертификат для HTTPS (замочек в адресной строке) и программа, которая его получает и продлевает.
- **rsync** — копирует папку на сервер, пересылая только изменившиеся файлы.
- **pm2** — следит за процессом Node на сервере: перезапускает после падения и после перезагрузки.
- **cron** — расписание на сервере: «каждую ночь делай бэкап».
- **Миграции** — файлы, которые по шагам описывают, как менялась структура базы данных.
- **GitHub Actions, workflow, Secrets** — GitHub сам запускает команды на каждый пуш; workflow — файл с этими командами; Secrets — место для паролей и ключей, которых нет в коде.
- **CORS** — запрет браузера обращаться с сайта на чужой адрес. Нам не нужен: игра и API на одном адресе.
- **Детерминированность** — одинаковые действия всегда дают одинаковый результат. Без неё сервер не сможет перепроверить партию.
- **tick, seed** — номер шага симуляции; начальное число для генератора «случайных» чисел, с которым последовательность можно повторить.
- **Прототип** — у любого объекта в JavaScript есть «родитель» со встроенными свойствами. Поэтому `TOWERS['constructor']` находит не башню, а встроенную функцию. `Object.hasOwn(TOWERS, id)` проверяет только собственные ключи.
- **inert, aria-modal** — атрибуты для экрана поверх страницы: `inert` выключает всё под ним (ни кликнуть, ни дойти клавишей Tab), `aria-modal` сообщает об этом скринридеру.
- **safe-area-inset** — отступы от выреза и скруглений экрана телефона. **overscroll-behavior** — что делать, когда страницу тянут дальше края (на Android — обновление страницы).
- **og:image** — картинка, которую мессенджер показывает рядом со ссылкой.

## Приложения

### A. Фаервол

Порты открываем по номерам. Готовый набор правил `'Nginx Full'` появляется только после установки nginx: если вызвать его раньше, команда выдаст ошибку, а порты 80 и 443 останутся закрытыми.

```bash
sudo apt install ufw          # на Ubuntu уже есть, на Debian 12 нужно поставить
sudo ufw allow OpenSSH        # СНАЧАЛА SSH, иначе потеряешь доступ. Если порт SSH не 22: sudo ufw allow <порт>/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw show added           # посмотреть правила ДО включения
sudo ufw enable               # на вопрос про SSH-соединения ответить y
sudo ufw status verbose       # должны быть 22, 80 и 443
```

После `ufw enable` не закрывай текущее окно с сервером, пока не убедишься, что во втором окне вход по SSH работает.

### B. Конфиг nginx

Сначала файл с заголовками безопасности `/etc/nginx/snippets/throne-security.conf` (без него `nginx -t` выдаст ошибку):

```nginx
add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header X-Frame-Options "SAMEORIGIN" always;
```

Потом сам сайт — файл `/etc/nginx/sites-available/throne-defense`:

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name throne-defense.ru www.throne-defense.ru;

    root /var/www/throne-defense;
    index index.html;
    server_tokens off;

    # Сжатие. По умолчанию nginx сжимает только HTML, а JS и CSS отдаёт как есть
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/css application/javascript text/javascript application/json image/svg+xml;

    include snippets/throne-security.conf;

    # Файлы сборки: в имени есть хеш, поэтому их можно хранить в браузере год
    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable" always;
        include snippets/throne-security.conf;
        try_files $uri =404;
    }

    # А саму страницу браузер каждый раз перепроверяет — иначе не увидит новую версию
    location = /index.html {
        add_header Cache-Control "no-cache" always;
        include snippets/throne-security.conf;
    }

    # Игра одностраничная, роутера нет: чего нет на диске — того нет (404)
    location / {
        try_files $uri $uri/ =404;
    }

    # Запросы /api/... уходят в Node. Пока бэкенда нет, отвечают ошибкой 502 — это нормально
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

- Заголовки вынесены в отдельный файл не случайно: `add_header` внутри `location` **отменяет** все `add_header` уровнем выше. Поэтому там, где есть свой `add_header`, файл с заголовками подключается ещё раз.
- `X-Frame-Options` запрещает открывать игру во фрейме на чужом сайте. Если площадкой станет VK или Telegram (этап 4), его придётся убрать или заменить.

Включение:

```bash
sudo apt install nginx certbot python3-certbot-nginx
sudo mkdir -p /var/www/throne-defense
sudo ln -s /etc/nginx/sites-available/throne-defense /etc/nginx/sites-enabled/
sudo rm /etc/nginx/sites-enabled/default   # необязательно: убрать заглушку «Welcome to nginx»
sudo nginx -t
sudo systemctl reload nginx
```

### C. HTTPS через certbot

Certbot получает бесплатный сертификат Let's Encrypt, прописывает его в конфиг nginx и сам продлевает. Запускать **после** того, как DNS указывает на VPS: Let's Encrypt проверяет домен через порт 80.

```bash
sudo certbot --nginx --redirect -d throne-defense.ru -d www.throne-defense.ru
sudo certbot renew --dry-run   # проверка автопродления
```

При первом запуске certbot спросит e-mail (на него придёт письмо, если автопродление сломается) и согласие с условиями. Флаг `--redirect` сразу включает перенаправление `http://` на `https://`.

Необязательно:
- **Один адрес вместо двух** (см. открытые вопросы). Сделать это **до** запуска certbot: в основном блоке оставить `server_name throne-defense.ru;`, а рядом добавить второй блок `server { listen 80; listen [::]:80; server_name www.throne-defense.ru; return 301 https://throne-defense.ru$request_uri; }`. Затем запустить certbot той же командой с обоими именами — он допишет HTTPS в оба блока. Проверка: `curl -I https://www.throne-defense.ru` должен ответить `301`.
- **HTTP/2.** Certbot дописывает `listen 443 ssl;` без него. Как включить, зависит от версии (`nginx -v`). До 1.25.1 (Ubuntu 22.04 и 24.04, Debian 12) — дописать `http2` в обе строки: `listen 443 ssl http2;` и `listen [::]:443 ssl http2;`. С 1.25.1 — отдельная строка `http2 on;`. На старой версии `http2 on;` вызовет ошибку в `nginx -t`.

### D. Выложить игру вручную (до этапа 2)

На сервер едет не исходный код, а собранная игра — папка `apps/web/dist/`. Команды запускать из корня репозитория, заменив `ЛОГИН` на своё имя на сервере:

```bash
# 1. Собрать и посмотреть, что изменится на сервере (-n — ничего не трогать, только показать)
npm run build && test -s apps/web/dist/index.html \
  && rsync -avn --delete apps/web/dist/ ЛОГИН@77.91.113.61:/var/www/throne-defense/

# 2. Если список выглядит разумно — то же самое по-настоящему
npm run build && test -s apps/web/dist/index.html \
  && rsync -av --delete --delay-updates --no-owner --no-group apps/web/dist/ ЛОГИН@77.91.113.61:/var/www/throne-defense/
```

- `/` в конце `dist/` означает «содержимое папки», а не саму папку.
- `--delete` удаляет на сервере файлы, которых больше нет в сборке (старые `index-XXXX.js`). Поэтому в `/var/www/throne-defense` не должно лежать ничего, кроме сайта: базу и загрузки хранить в другом месте. Побочный эффект: у игрока с открытой вкладкой до обновления страницы может не подгрузиться шрифт — для нашего проекта это терпимо.
- `&&` и `test -s …/index.html` — предохранитель: если сборка упала или получилась пустой, `rsync` не запустится и не сотрёт работающий сайт.
- `--delay-updates` подменяет файлы разом в конце, а не по одному; `--no-owner --no-group` не переносит на сервер владельца файлов с твоего компьютера.

Если не хватает прав, сначала на сервере: `sudo chown ЛОГИН /var/www/throne-defense`.
